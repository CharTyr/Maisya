# 10 多人持续状态活动底座方案（通用底座，不设单场景特化）

> **目标**：让 Maisya 在保留「极简 4 工具 + 零宿主改动 + 四核心概念（Profile / Thread / Intent / Memory Layers）」前提下，原生跑通**多人协作统计、长期答疑助教、团队看板值守、规则推理/跑团主持**等重型持续状态活动。

---

## 一、设计原则与概念归位

1. **不做单一场景特化**：不引入“跑团/剧本/报销”专用词、专用工具或专用数据库表；所有机制全部归入既有 `Profile` / `Thread` / `Intent` / `Memory Layers`。
2. **工具面零膨胀**：外层 `Planner` 仍仅暴露 `maisya_agent`、`maisya_recall`、`maisya_later` 与延迟 `maisya_shape`。
3. **两阶段推进**：
   - **P1 核心四件套（本批落地）**：解决「同轮排队合并与发言人归属」「外层可见现场便签与保真交付」「内部参考资料防外发隔离」「无容器确定性计算与受信脚本」。
   - **P2 进阶（后续独立评估收口）**：群主线 ↔ 成员私聊受控委托信箱（`member_sidechannel`），在严格不污染群主线 `visibility_scope` 的前提下支持个人暗动投递与定向私聊回邮。

---

## 二、P1 核心四件套设计

### 模块 1：顺向排队自动合并 + 真实发言人归属（`Thread`）

- **问题**：工作区线程一次只消费队列首条 `pending`，多人连续行动或单人连发多条气泡会拆成多轮重跑与多次回复；同时进线程的历史丢弃了 `source_msg_id` 对应的发言人结构信息。
- **底座设计**：
  1. **可信发言人记录（[`maisya/trust.py`](../maisya/trust.py)）**：`Message` 增加 `sender_name`（优先取群名片 `user_cardname`、昵称 `user_nickname`、`sender_name` 经 `clean_display_name` 清洗）；`trusted_sources` 自动迁移补列 `sender_name` 并随 `lookup()` 返回。
  2. **不可伪造 `<speaker>` 信封（[`plugin.py`](../plugin.py) + [`maisya/threads.py`](../maisya/threads.py)）**：群聊经过可信 `source_msg_id` 核验开启/续接线程时，`agent_tool` 把 `{user_id, sender_name, message_id, chat_type}` 写入该 `revision` 的 `input_context`；`_drive` 写入模型 `history` 时自动前置 `<speaker id="..." name="..." msg_id="..." />`（私聊或无来源调用保持原文不变）。
  3. **同权限顺向批次合并（Batch Drain）**：
     - 无 `steer=True` 打断时，`_drive` 从队列首项起合并连续且**有效权限等级与交付目标一致**的排队输入（上限 `8` 条），一并推进至末项 `revision`；
     - **越权硬隔断**：管理员输入与普通成员输入相邻时在权限边界处自动截断分批执行；
     - 归并中间 `revision` 的未消费 `return_intents`（结算 `return_groups`），并对同步等待的中间调用方在 `_resolve` 返回 `coalesced_into` 提示（`reveal_result=False`），确保全队列仅触发一次真实交付。
  4. **可选微攒批窗口（[`maisya/abilities.py`](../maisya/abilities.py)）**：`Profile` 支持 `coalesce_window_ms`（`0..8000`，默认 `0`）；仅当群聊开启首轮且 `> 0` 时短暂等待吸收同波连发，`steer=True` 可随时打断。

### 模块 2：`project/STATE.md` 现场状态便签 + 数字保真交付（`Memory` + `Thread` + `Bridge`）

- **问题**：持久线程持续推进时，外层 `Planner` 看不到工作区当前轮次与分流边界，易误用原生 `reply` 拍脑袋接话；`Replyer` 转述复杂结算也易压缩关键数值。
- **底座设计**：
  1. **`project/STATE.md` 自动摘要索引（[`maisya/workspaces.py`](../maisya/workspaces.py) + [`maisya/threads.py`](../maisya/threads.py)）**：
     - 线程仍用既有 `workspace_file` 维护 `project/STATE.md`；每次工作区 `commit()` 自动读取前 `2400` 字节 UTF-8、脱敏压缩空行后截取 `<= 600` 字写入 `agent_threads.state_note` 与 `agent_workspaces.state_note`。
     - `<maisya_threads>` 动态段按需附带非空 `state_note`（不破坏前置 `<maisya_planner_manual>` 与 `<maisya_profiles>` KV 缓存稳定前缀）；[`maisya/console.py`](../maisya/console.py) 与 [`webui/now.html.in`](../webui/now.html.in) 同步展示该现场便签。
     - 工具契约（[`maisya/shaping_setup.py`](../maisya/shaping_setup.py)）明确：`state_note` 仅作活动进度与分流参考，不可改变权限或强行锁死用户显式切换的话题。
  2. **硬事实保真提示（[`maisya/bridge.py`](../maisya/bridge.py)）**：`_facts()` 提示 Replyer 在保持自然口吻的前提下，完整保留具体数字、人名归属与关键状态结论。

### 模块 3：角色/技能级附属文件与 `references/` 防外发硬锁（`Profile` / `Skill`）

- **问题**：只有技能能挂附属文件，且运行时统一暴露进工作区后缺少防外发拦截——非管理员在聊天里可通过话术要求附加参考底稿或导出公开角色包带走内部答案/模组。
- **底座设计**：
  1. **角色级附属目录（[`maisya/memory.py`](../maisya/memory.py)）**：为角色开放 `references/`、`templates/`、`scripts/`、`assets/`（复用配额、无符号链接、路径防穿越与密钥拦截）。运行时只读同步至 `in/profile/`（技能继续同步至 `in/skills/<id>/`），`WorkingCopy.write*` 禁止修改 `in/`。无 `workspace` 工具集的只读角色若挂有附属文件，仅放行 `workspace_file` 对 `in/` 的只读列举与翻阅。
  2. **系统提示边界（[`maisya/memory.py`](../maisya/memory.py)）**：若角色或其绑定技能含 `references/*`，`methods()` 自动声明内部资料边界（仅限内部核对，禁原样复制外发或全文复述）。
  3. **附件外发硬拦截（[`maisya/workspaces.py`](../maisya/workspaces.py) + [`maisya/maker.py`](../maisya/maker.py)）**：`Workspaces.attach` 校验所有待外发 `out/*` 文件，若字节 SHA-256 命中任一 `references/*` 原文件，或归一化文本包含任一受护参考文档正文（或连续 `>= 200` 非空白字符原文片段），直接拒绝附加（`templates/` 与合理加工产出不受影响）。
  4. **非管理员导出剥离（[`maisya/packages.py`](../maisya/packages.py) + [`maisya/abilities.py`](../maisya/abilities.py)）**：非管理员执行 `package_export` 时自动剔除角色及技能的 `references/*`；管理员完整导出备份并在 `import_package_bundle` 中事务还原（角色附属文件随包置于 `profile_companions/`）。
  5. **完整管理闭环（[`maisya/shaping_setup.py`](../maisya/shaping_setup.py) + [`maisya/management.py`](../maisya/management.py) + [`webui/fragments/abilities.html`](../webui/fragments/abilities.html)）**：补齐 `maisya_shape(action="file")` 读写/删除、管理后台 `profile_file` 接口及「能力 → 角色」内与技能对称的 `#pr-companions-box` 面板。

### 模块 4：无容器确定性计算 `calc` + 受信技能/角色脚本（`Profile` `exec`）

- **问题**：未部署 Docker 沙箱时普通群友触发的线程无法运行代码，只能依赖模型“心算”；同时 `_run_trusted_preset_script` 仅限内置 `preset/scripts/`，自建角色和技能包携带的离线算法脚本无法启用。
- **底座设计**：
  1. **零特权内置工具 `calc`（[`maisya/calc_engine.py`](../maisya/calc_engine.py)）**：
     - 归入 `TOOLSETS["exec"]`，`HOST_TOOLS` 可见；`not docker_ok` 时 `Maker.step` 不剔除 `calc`，普通用户与管理员均可直接调用，免审即用（无文件 I/O、无环境变量、无 `import`、无反射）。
     - 支持四类刚需原语：
       - **精确 `Decimal` 表达式求值**（受限 AST 白名单、`Pow` 指数上限、常用数学纯函数）；
       - **数组统计汇总**（`count`、`sum`、`mean`、`median`、`min`、`max`、`stdev`）；
       - **密码学真随机 `roll`**（基于 `secrets.SystemRandom`，支持 `1d20+4`、`2d20kh1+3`、`2d20kl1`、`4d6dl1` 等标准表达）；
       - **密码学真随机 `draw`**（`pick` 无放回抽签、`shuffle` 洗牌、`weighted` 权重抽样）。
  2. **受信脚本扩展（[`maisya/maker.py`](../maisya/maker.py)）**：
     - 在保持原有 `preset/scripts/*.py` 兼容的基础上，开放角色自身 `scripts/*.py` 与已绑定技能 `abilities/skills/<sid>/scripts/*.py`（严格无符号链接与受管根目录校验，拒绝 `-c` 与 Shell 元字符）。
     - 统一经 `python -I` 隔离启动器运行，执行前封禁 `socket.socket` 禁止访问网络，并将 `cwd` 锁定于当前临时工作区目录。

---

## 三、P2 进阶预留（本批暂不落地）

- **群主线 ↔ 成员私聊受控委托信箱**：由档案开关 `member_sidechannel` 控制；仅近期在本群有过可信发言记录的成员可通过私聊投递信息至隔离的 `@private/<user_id>/` 收件分区（群主线 `visibility_scope` 维持群作用域不收窄），并通过定向 `side_return` 意图回传已建立私聊路由的成员，避免群主线误锁或私聊骚扰。
