# 宿主接口事实（Maisya 专用核查基线）

> 以下条目均基于 `MaiBot 1.3.20`、`maibot_sdk 2.21.0` 宿主源码核实与历史实测整理；写代码前先查本文件，未实测项已明确标注 **〔待实测〕**。

## 1. 插件装载与基本契约〔源码 + 实测〕

- `plugin.py` 模块级必须暴露 `create_plugin()`；`__init__.py` 只做导出。
- 插件类必须实现异步方法：`on_load()`、`on_unload()`、`on_config_update(scope, config_data, version)`（`src/plugin_runtime/runner/plugin_loader.py`）。
- `_manifest.json` 为严格模型（`extra="forbid"`）：必填 `i18n`、`author.url` 和 `urls`；`plugin_type` 支持显式声明。用到的每项宿主能力都必须写进 `capabilities`（声明 `@Tool` 与 `@API` 本身无需额外 capability，认领 WebUI 上传图片需 `webui.claim_upload`）。
- SDK 兼容区间写实测端点 **`2.8.1`–`2.21.0`**，宿主区间写 **`1.0.0`–`1.4.99`**。
- **文件监控触发范围〔源码：`src/plugin_runtime/integration.py:2160-2172`〕**：
  - `_is_watchable_plugin_source` 仅匹配 `_manifest.json` 与 `.py` 文件，改动会触发跨插件热重载。
  - 每个插件的 `config.toml` 有独立订阅，改动只触发本插件 `on_config_update(scope="self", ...)`（除非 `enabled` 开关翻转）。
  - 修改 `.html` 等非 `.py` 静态文件**不会**触发插件热重载。
- **插件更新清理边界〔源码：`src/webui/routers/plugin/management.py:180` `_restore_known_user_files`〕**：宿主官方后台非 git 覆盖更新插件时，仅把旧插件目录中的 `config.toml` 与 `config_back/` 拷回新目录，其余未知子目录与文件会被整棵清理。因此运行期用户资产（凭据保险箱、派生专岗、技能库、记忆、心跳手账与工作区）**必须统一存放在插件目录之外的 `<宿主根>/data/maisya/`**；同时将 `_manifest.json`、`webui.json`、`plugin.py` 置于仓库根目录即可直接支持官方后台一键安装与点按钮更新。
- 全部第三方插件共用同一个 `third_party` Runner 进程与事件循环：任何 async 路径严禁同步网络阻塞或长锁等待；连续 3 次钩子超时/异常会触发整插件 60～300 秒熔断。

## 2. 收消息、消息别名与管理员防串号〔源码 + 实测〕

- **`chat.receive.after_process`**：消息入库前触发，`kwargs["message"]` 正文在 `processed_plain_text`（无 `text` 键），`timestamp` 为字符串；永远返回 `{"action": "continue"}`，绝不 `abort`。
- **防攒批串号风险〔源码：`component_query.py:814-853`、`reasoning_engine.py:399+`〕**：多条消息合并进同一轮 `planner` 时，工具上下文自动注入的 `user_id` 取缓冲末尾最新消息发送人，**不等于指令原消息发言人**。因此管理员级操作必须带 `source_msg_id`，反查插件在 `chat.receive.after_process` 记录的可信 `(msg_id, session_id, platform, user_id)` 表（并排除 `is_plugin_relayed` 代投消息）。
- **消息 ID 短别名〔源码：`src/maisaka/context/message_id_alias.py:19-26`〕**：原 ID 长度 `> 12` 时模型看到 `"m" + base32(sha1(raw))[:6]`；宿主调插件工具前虽会自动展开参数别名，可信消息表仍须同时索引原 ID 与短别名。
- **宿主管理员配置读取〔源码：`src/core/local_operator.py`、`src/chat/message_receive/bot.py`〕**：可通过 `config.get("plugin.permission")` 只读继承宿主操作员名单，命令上下文另带 `is_local_operator` 标记。

### M0 当前宿主复核（2026-11-12，源码 + 隔离契约）

- `PluginMessageUtils._session_message_to_dict`（`src/plugin_runtime/host/message_utils.py`）把 `platform` 放在消息顶层；`message_info` 内只含用户、群和 `additional_config`。代投标记是 `additional_config.relayed_by_plugin`；不存在顶层 `is_plugin_relayed` 字段。
- `src/core/local_operator.py` 仅认可 `platform == "bot_console"` 且 `additional_config.is_local_operator is True` 的本地操作员；代投消息优先拒绝。管理员名单是 `platform:user_id` 字符串列表，只把平台名转小写，用户 ID 保持大小写。
- SDK `ctx.paths.data_dir` 由宿主 `build_plugin_paths` 分配为 `<宿主根>/data/plugins/<plugin_id>`。Maisya 验证这个结构后，把运行期资产放在同一 `data` 下的 `maisya/`；测试通过隔离的 `PluginPaths` 注入路径，不依赖 CWD。
- `chat.receive.after_process` 可以返回 `modified_kwargs.message` 替换消息；普通消息返回 `continue`。显式 `/vault` 输入先替换 `processed_plain_text` 和 `raw_message`，随后匹配原生 `@Command`。
- 原生命令返回三元组 `(success, response, intercept_message_level)`；非零拦截等级消费消息，但宿主 `_handle_command_processing_result` 仍会保存消费后的消息。因此凭据必须在命令链前完成脱敏。
- 当前宿主的 `ManifestValidator`、生命周期验证、消息序列化器与权限规则已在 `tests_host/test_contract.py` 实跑，未加载到线上插件目录。

## 3. `planner` / `replyer` 前后钩子与内置工具替换〔源码〕

- **`maisaka.planner.before_request`**（`chat_loop_service.py:1238-1285`）：
  - 载荷含 `items`、`item_schema_version`、`tool_definitions`、`session_id` 等 7 键（注意是 `items` 不是 `messages`）。
  - `Replyer` 复用同一底层循环但 `tool_definitions == []`，必须据此区分 `planner` 与 `Replyer` 轮次。
  - 返回 `modified_kwargs` 时可过滤 `tool_definitions`（例如在启用会话仅剔除宿主内置 `subagent` / `subagent_status` / `subagent_stop`，100% 保留宿主原生工具如 `query_memory` 及其他第三方插件注册的 `@Tool`；或在无管理员发言轮次隐藏管理员工具）；未改动 `items` 时宿主跳过反序列化开销。
- **插件 `@Tool` 执行超时与同轮顺序执行〔源码：`component_timeout.py:6`、`reasoning_engine.py:2395`〕**：
  - 宿主调用插件 `@Tool` 的默认 RPC 超时为 **60000ms（60 秒）**（可通过组件 `timeout_ms` 元数据调整）。
  - 同一轮 `planner` 输出多个 `tool_calls` 时，宿主在 `for` 循环中**顺序逐个 awaiting 执行**。因此 `maisya_agent` 可以对单个线程使用最多 `30` 秒等待窗口；同轮开启多个线程时传 `wait_seconds=0`，让线程并行运行。
- **跨插件 `@API` 互调〔源码：`capabilities/registry.py:101`、`capabilities/components.py:92` + SDK 源码核实〕**：
  - 宿主提供 `api.list`、`api.get`、`api.call` 能力，支持跨插件调用公开的 `@API`（如空间说说、Soul 状态等）。
  - 注意 SDK `PluginContext._CAPABILITY_RESULT_KEYS['api.call'] == 'result'`：通过 `ctx.call_capability("api.call", ...)` 调用且返回含 `"result"` 键的成功信封时，SDK 会自动解包直接返回 `result` 本身（若外部 API 返回 `None`、`0`、`[]` 或字符串，调用侧直接拿到这些裸值；仅当失败或 `success is False` 时保留信封字典/抛出错误），因此兼容层必须区分 `success is False` 与合法裸值 `None`。
- **工具可见性与范围**（`component_query.py:276-285`、`component_registry.py:125`）：
  - `@Tool(..., chat_scope="all", visibility="visible")` 同时对群聊与私聊注册且直接进入 `tool_definitions`；省略 `visibility` 默认变成 `"deferred"`（藏在 `tool_search` 后）。
  - 工具报错必须写 `error` 或 `message` 字段（仅写 `content` 在 `success=False` 时会被宿主丢弃）。
- **`maisaka.planner.after_response`**：`output_items` 中 `FunctionCallItem` 含 `tool_call.{call_id, func_name, args}`；注意宿主内置 `reply` 工具不结束回合（`stop` / `wait` 才收尾）。
- **`maisaka.replyer.before_request`**（`src/chat/replyer/maisaka_generator_base.py`）：可在当次生成前单次垫入 `extra_prompt` 核实小抄（〔端到端效果待实测〕）。

## 4. 跨会话主动唤醒、人物印象与媒体发送〔源码 + 实测〕

- **打开会话与主动触发〔源码 + 实测〕**：
  - `chat.open_session(platform, chat_type="private"|"group", user_id=..., group_id=...)` 打开或获取目标会话 `stream_id`；`pulse` 结合持久化的 `session_routes` 在遇到 `"未找到已存在的聊天流"` 时先尝试重开一次，已通过宿主隔离契约实测（〔私聊新建流待在线实测〕）。
  - `maisaka.proactive.trigger(stream_id, intent, reason, priority, metadata)` 往内存上下文注入 `<plugin_proactive_task>` 并唤醒目标会话跑一轮 `planner`（不落消息库；群 `talk_value == 0` 时静默）。
- **记忆与人物查询〔源码 + 实测〕**：`knowledge.search(...)` 只读查 `A_Memorix` 长期记忆；`person.get_id` / `person.get_value`（`data.py:585-631`）只读查人物关系印象。
- **发送消息身份对齐〔源码 + 实测〕**：`send.hybrid` 代机器人发图文/引用时必须传 `sync_to_maisaka_history=True, maisaka_source_kind="guided_reply"`，否则当轮内存上下文会把机器人刚发的话误判成群友发言。当同一投递包含 `file` 附件段时，`Share` 会先发送文字/回复/图片主段，再将每个 `file` 附件拆分在主消息之后单独发起一次带相同 `sync_to_maisaka_history=True, maisaka_source_kind="guided_reply"` 参数的 `send.hybrid` 调用（主消息失败则跳过文件跟发）。

## 5. 插件 WebUI 扩展页面（`webui.json` v2）〔源码，真机交互待实测〕

核对自 `src/plugin_runtime/webui_schema.py`、`src/webui/routers/plugin/webui_extensions.py`、`dashboard/src/components/plugin-custom-page.tsx` 与 `dashboard/src/lib/plugin-custom-page.ts`：

- **声明规范**：插件根目录放 `webui.json`（`<= 128 KiB`，禁符号链接），`schema_version: 2`，至少 1 页、最多 20 页。`placement: "workspace"` 挂入宿主顶部工作区切换栏（必填 `workspace_title`）。M0 的单页 `custom` 骨架已通过真实宿主 `load_webui_extension`。
- **自定义 HTML 页（`mode: "custom"`）**：
  - `required_capabilities` 需含 `"custom_pages"`（使用数组/对象参数另加 `"structured_arguments"`，上传图片另加 `"image_upload"`）。
  - `entry` 指向插件目录内相对 `.html` 文件（单页 `<= 2 MiB`，总计 `<= 8 MiB`），支持 `layout: "viewport"` 或 `"document"`。
- **CSP 沙箱与 `window.maibot` 桥接**：
  - 宿主在 `srcdoc` `<iframe>` 头部强制注入 `default-src 'none'; script-src 'unsafe-inline' blob:; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; media-src data: blob:; connect-src 'none'`——**严禁任何外链 CDN、`fetch`、`WebSocket` 或 `SSE`**，必须构建为内联自包含单文件 HTML。
  - 页面内通过 `window.maibot` 调用：`await window.maibot.ready`、`query(name, args)`、`action(name, args)`、`upload(name, file, args, options)`、`navigate(pageId, state)`；`window.maibot.context` 与 `CustomEvent('maibot:context')` 自动同步宿主明暗色、Dashboard 风格、语言与字体；声明 `confirmation` 的 `action` 自动弹宿主原生确认框。
- **网关硬配额（设计红线）**：
  - 仅绑定插件静态 `@API(..., version="1")`（每页最多 `10` 个 `queries`、`20` 个 `actions`），所有请求强制验宿主 `maibot_session` Cookie。
  - **每插件并发硬顶为 2**（后端 `_inflight >= 2` 返 `429`，前端 `pending.size >= 2` 直接抛错）：轮询必须做成单路串行，始终留出第 2 个槽位响应用户点击。
  - 单次 `@API` 超时 **10000ms**；入参 JSON `<= 64 KiB`（`navigate` 状态 `<= 4 KiB`），返回 `result` JSON `<= 512 KiB`（最大深度 12、最多 20000 元素）。
  - 修改 `.html` 后可通过宿主 `POST /api/webui/plugins/runtime/webui/{plugin_id}/reload`（界面刷新按钮）热更新文档快照，不触发插件重载。

## 6. 线程结果回接相关边界〔源码，端到端待实测〕

2026-11-12 已只读复核当前宿主源码，结果补入、重试参数和唤醒 RPC 经过真实 SDK 隔离契约；最终对话效果待联调。

- **`Replyer` 看不到工具结果**：`src/chat/replyer/maisaka_generator_base.py:973-985` 只保留非通知的 `SessionBackedMessage`；工具结果与内部上下文被过滤。`src/maisaka/builtin_tool/reply.py:617` 调 Replyer 时传空 `reply_reason`。因此纯文字线程结果通过 `maisaka.replyer.before_request` 补入事实。
- **`extra_prompt` 与重试参数**：`maisaka_generator_base.py:1124-1141` 在每次生成尝试前调用 Hook，入参含 `session_id`、`request_type`、`attempt`、`reply_message_id`、`extra_prompt`、`reply_tool_args`。返回的 `extra_prompt` 拼入 `【额外回复要求】`（`:849`）；返回的 `reply_tool_args` 成为后续尝试的参数，适合携带同一次生成的插件不透明标记。每次尝试的 `extra_prompt` 从原始要求重新取得，插件需在重试时重新提供事实。原生回复类型为 `maisaka.replyer`，文档表达能力使用 `plugin.replyer`，两者分别处理。
- **插件代发身份**：`send.*` 默认使用 `maisaka_source_kind="plugin_send"`。插件代 MaiBot 发出的消息必须传 `sync_to_maisaka_history=True, maisaka_source_kind="guided_reply"`，当轮上下文才会把它识别为 MaiBot 自己的发言。
- **`maisaka.reply.generate`**：
  - 实现：`src/plugin_runtime/capabilities/core.py:367-420` → `DocumentReplyGenerator`。
  - 行为：校验聊天流存在，提取本群最近 10 条聊天命中的表达习惯，拼接 MaiBot 人设和语气，用 Replyer 模型生成文本并返回给插件。
  - 边界：它只返回文本，不直接发送消息；不经过错字模拟与拆句；不要求原消息仍在当前历史窗口内。默认模板偏向文档写作，需要用 `format_instruction` 或 `maisaka.replyer.before_model_request` 改成群聊短句语境〔待实测〕。
  - 兼容：旧宿主未注册该能力时，运行期调用会抛异常；插件应捕获并使用 `planner` 提供的简短表达作为回退。
- **`maisaka.proactive.trigger`**：
  - 实现：`src/plugin_runtime/capabilities/core.py:331-365` → `src/maisaka/runtime.py:665 enqueue_proactive_task`。
  - 入参：`stream_id`、非空 `intent`，可选 `reason`、`priority`、`metadata`。返回成功表示任务已入队，并带 `task_id` 与 `queued`；不表示已发言。
  - 行为：向目标会话的内存上下文追加一段 `<plugin_proactive_task>`，然后唤醒一轮 `planner`；最终是否开口由 MaiBot 决定。
  - 边界：注入内容不写消息库，宿主重启后消失；目标聊天流必须已存在；群回复频率为 `0` 时进入静默处理。
- **`send_service.before_send`**：宿主存在该 Hook，可整体替换出站序列化消息。Maisya 当前设计不依赖它合并线程媒体；准确链接、媒体和旧锚点统一由 `share` 处理。

- **M2 当前策略〔插件实现 + 隔离契约〕**：只有来自已核验用户消息的后台 `return` 自动唤醒；普通自主探索留在索引中。意图在结果提交时事务写入，按输入版本检查有效性；同轮同来源合并为回接组，认领后不会在重载时重复投递。RPC 拒绝或状态不明时保留结果供后续检索。`share` 尚未实现。

## 7. M1 模型、只读能力与上下文接入（2026-11-12）

以下接口已只读核对当前宿主 1.3.20 源码。载荷与 SDK 兼容性已通过服务器隔离契约；模型与联网响应由测试 RPC 替身提供。

- **模型循环**：`src/plugin_runtime/capabilities/core.py` 的 `_cap_llm_generate_with_tools` 接受 `prompt` 消息列表、OpenAI function `tools`、`task_name`、`model_name` 与 `max_tokens`。它调用宿主统一 `LLMServiceRequest`，插件自行执行返回的工具；宿主不会代插件运行这些工具。
- **模型结果**：`LLMServiceResult.to_capability_payload`（`src/common/data_models/llm_service_data_models.py`）返回 `success/response/tool_calls`。工具项是 `{id, function: {name, arguments}}`，`arguments` 为字典；线程将其规范化为 Chat 风格消息，与 `role="tool"`、`tool_call_id` 配对。宿主 `_build_prompt_context_factory` 实跑通过该格式。
- **能力 RPC 默认超时与异常类型〔源码：`runner_main.py:870-922`、`rpc_client.py:209-217`〕**：`PluginContext.call_capability` 显式接收 `timeout_ms: int | None = None`；未传时宿主 Runner 默认以 `30000ms` 超时等待 `rpc_client.send_request`。超时或断连时 `RPCClient` 直接抛出继承自 `Exception`（而非 `RuntimeError`/`TimeoutError`）的 `RPCError`，联网服务抛同样继承 `Exception` 的 `WebSearchError`。插件对长耗时能力（模型/联网/混合发送）需显式传入更大 `timeout_ms`，并在调用包装与线程主循环兜底捕获 `Exception`（保留 `asyncio.CancelledError`）。
- **实例目录环境变量隔离〔源码：`src/common/paths.py`、`src/config/config.py`〕**：设置 `MAIBOT_INSTANCE_DIR` 可同时隔离宿主的 `BOT_CONFIG_PATH`、`MODEL_CONFIG_PATH`、`LEGACY_ENV_PATH` 与 `data/MaiBot.db`，用于独立目录跑真实大模型与联网能力冒烟而不触碰线上配置或活库。
- **统一联网配置生效条件〔源码：`src/web_search/config.py` + 隔离实测〕**：`src/plugin_runtime/capabilities/registry.py` 注册 `web.search` 和 `web.fetch`，实现位于 `capabilities/web.py`。搜索只支持 `query`、`max_results`（宿主范围 `1～20`）；读取只支持 `url`。`resolve_web_search_config` 仅以 `model_config.model_task_config.web_search.model_list` 是否选中服务作为启用开关——仅在 `[web.services.*]` 定义服务而未在功能分配中选择时，`enabled` 仍为 `False`，此时调用 `web.search` / `web.fetch` 会抛出 `WebSearchError("统一联网功能未启用")` 或 `"当前操作未配置联网服务"`。
- **`config.get_plugin` 跨插件只读配置读取〔源码：`capabilities/components.py`、`maibot_sdk/context.py` + 隔离契约〕**：`_manifest.json` 声明 `config.get_plugin` 后，可通过 `ctx.call_capability("config.get_plugin", plugin_name=...)` 读取目标已加载插件的归一化配置字典。`PluginContext._CAPABILITY_RESULT_KEYS["config.get_plugin"] == "value"`，SDK 会在检查 `success` 前直接解包 `"value"` 字段——目标插件未加载时，宿主信封 `{"success": False, "value": None, "error": ...}` 会被解包为裸 `None`，调用侧须同时兼容裸 `dict`、`None` 与原始信封格式。Maisya 仅在 `auto` 回退或显式选择 `google_search_plugin` 时按需读取 `xxxxx7258.google-search-plugin` 配置，密钥仅在单次请求作用域内使用并在返回与报错时统一脱敏，绝不持久化或外泄。
- **SDK 自动解包**：`PluginContext.call_capability` 会把 `message.get_recent` 解包为消息数组、`message.get_by_id` 解包为消息或 `None`、`knowledge.search` 解包为正文字符串。插件兼容直接值与宿主原始信封；只检查信封会误判真实 SDK 返回值。
- **会话读取**：消息能力入参为 `chat_id`。Maisya 从工具执行上下文注入该值，不在模型工具参数中开放；读取后继续核对返回消息的 `session_id`。`knowledge.search`（`capabilities/data.py`）把 `chat_id` 和默认开启的 `respect_filter` 转交 `memory_service.search`。
- **视觉读取**：`llm.generate_for_image` 使用 `image_base64`、`image_format`、`prompt` 和 `task_name="vlm"`。图片从当前会话引用消息中装载，只把视觉模型生成的文字送回探索线程；识图端到端内容质量待联调。
- **请求上下文**：追加的 `UserMessageItem` 必须有 `meta.item_id`、`meta.logical_turn_id`、ISO 格式 `meta.timestamp` 和文本 `parts`。M1 的实际追加项已通过宿主 `deserialize_prompt_items(..., mode=REQUEST_CONTEXT)`；既有系统项保持原样。
- **来源与权限策略〔Maisya 实现 + 隔离契约〕**：`source_msg_id` 在原生工具 schema 中可选；普通只读能力允许 MaiBot 无用户来源自主调用。显式提供的来源必须在最近 `300` 秒内记录且不是插件代投，受限能力始终要求真实来源与权限。宿主上下文中的 `user_id` 不授予管理员权限。可信消息索引保留 `24` 小时或至多 `10,000` 条，保留期限不延长授权有效期。
- **转向与归档载荷〔隔离契约〕**：旧方向未执行的工具以跳过结果补齐 `tool_call_id` 配对，宿主原生 Chat 解析器可接受；上下文归档按完整工具调用/结果组裁剪，保留部分同样通过原生解析器，原始事件可按当前线程回读。模型转向判断与回读工具选择的实际效果需真实模型联调。
