# 08 心跳恢复方案

> **进度**：✅ 第 1～7 步已全部落地（配置与兼容迁移、两层每日额度、三步心跳与 `heartbeat_ticks`、对话调整面、管理台三段档位/手账状态条/现场最近心跳记录与文档同步）。

> **目标**：恢复原蓝图「有脉搏但极度克制」的心跳形态，同时保持 v0.3「默认零打扰、细节交给用户与 MaiBot 对话调整」的减负方向。MaiBot 仍是唯一开口者：心跳只产生意图或探索线程，永远不直接发消息。

## 一、已定决策

1. **默认关**：心跳（逛逛 + 想念）默认关闭；**事后惦记保留默认开启**。
2. **用档位**：用户与 MaiBot 只面对「关 / 克制 / 活泼」三档，代码负责映射到具体节奏；原始字段只作高级覆盖。
3. **恢复原设计**：随机抖动间隔 + 便宜判断，多数心跳原地 `HEARTBEAT_OK` 静默，有由头才起线程或唤醒会话。
4. **想念并回心跳**：一次心跳统一决定「这次逛逛 / 想起某个熟人 / 静默」，不再有独立的久违计时循环。
5. **额度两层**：全局每日总量 + 单会话每日上限。

## 二、档位（`heartbeat_mode`）

| | `off`（关，默认） | `gentle`（克制） | `lively`（活泼） |
|---|---|---|---|
| 事后惦记（`afterglow`） | 开 | 开 | 开 |
| 心跳跳动 | 不跳 | 基准 180 分钟 | 基准 90 分钟 |
| 随机抖动 | — | 基准 × 0.7～1.4 | 同左 |
| 想念阈值（熟人会话安静多久算久违） | — | 72 小时 | 24 小时 |
| 逛逛（需 `HEARTBEAT.md` 自主探索方向非空） | — | 可选 | 可选 |

- 分会话分寸 `chat_proactive_levels`（`quiet` / `care` / `lively`）语义不变，与档位正交：`quiet` 会话不收任何主动消息；`care` 群聊不收偶遇分享；`lively` 全收。
- **高级覆盖**（`0` = 跟随档位）：
  - `heartbeat_interval_minutes`：`0` 或 `30..1440`；
  - `longing_quiet_hours`：`0` 或 `12..720`（**语义变化**：`0` 不再表示「关闭想念」，关闭统一走 `heartbeat_mode=off`）。
- **兼容字段 `heartbeat_enabled`**：不再落盘为独立开关；读接口按 `heartbeat_mode != "off"` 派生返回；写接口收到 `true` 时若当前为 `off` 则改为 `gentle`，收到 `false` 时改为 `off`。

## 三、一次心跳的流程

**跳动前置条件（全部为代码判断）**：插件启用、`heartbeat_mode != off`、不在睡眠时段、没有正在运行的自身线程、已到 `next_at`。下次时间 = 本次时间 + 基准间隔 × 随机抖动；最近一次跳动时间仍持久化在 `social_state('__self_heartbeat__')`，防重启后连跳（跨进程最小间隔 = 基准 × 0.7）。

**第 1 步：代码收集由头（零模型调用）**
- **想念候选**：已启用会话，且同时满足：分寸不是 `quiet`、`acquaintance_allowed`、社交闸放行（不在未回锁中）、`longing_ready`（同会话 7 天冷却）、该会话额度可用、真人安静时长 ≥ 想念阈值、真人数 ≥ 3。按安静时长降序，最多取 5 个。
- **逛逛可用**：`HEARTBEAT.md` 的「## 自主探索方向」非空，且心跳档案已启用并允许自主运行。
- 两者都没有：记为 `ok:no_reason`，直接结束，不调模型。

**第 2 步：一次便宜判断（仅在有由头时调用）**
- 调用宿主 `llm.generate_with_tools`：`task_name="utils"`、`tools=[]`、`max_tokens<=200`，超时 20 秒。
- 输入：`## 气质与分寸`、自主探索方向、近期 `JOURNAL.md` 尾部（脱敏后约 400 字）、候选列表。每个候选只给 `ref`、会话类型、显示名与安静小时数，**不放任何会话 `MEMORY.md` 或聊天原文**。
- 输出严格 JSON，三选一：
  - `{"action":"ok"}`
  - `{"action":"miss","ref":"c1","reason":"一句话由头"}`
  - `{"action":"explore","topic":"一句话方向"}`
- 提示词默认偏向 `ok`（「拿不准就静默」）。模型失败、超时、JSON 非法或 `ref` 不在候选内，一律按 `ok` 处理。

**第 3 步：落地**
- `ok`：原地静默（`HEARTBEAT_OK`）。
- `miss`：写入 `kind="proactive", source="longing"` 意图，`due_at=now`。走现有意图管线二次过闸后唤醒目标会话 `planner`，由 MaiBot 自己决定说不说、怎么说。
- `explore`：沿用现有自身探索线程（`owner="self"`、工作区 `heartbeat`），把 `topic` 附进提示。线程仍可经 `thread_later(kind="serendipity")` 提议偶遇分享，按新额度规则过闸。

**玻璃盒记录**：每次跳动写一行 `heartbeat_ticks(at, outcome, detail)`，只保留最近 50 行。`outcome` 取值：`ok:no_reason`、`ok:model`、`ok:fallback`、`miss`、`explore`、`skip:<原因>`。概览与「现场」页读取最近若干条，对应原蓝图「最近心跳脉搏记录（静默或触达原因）」。

移除独立的 `Pulse._longing()` 循环，其候选筛选逻辑并入第 1 步。

## 四、额度（全局总量 + 单会话上限）

- `daily_proactive_limit`：**全局**每日主动总量，默认 `3`，范围 `0..50`（取代原「群聊 / 私聊各自计数」的分舞台口径）。
- `per_chat_daily_proactive_limit`（新增）：单会话每日上限，默认 `1`，范围 `0..10`。按 `_social_aliases` 合并同一会话的流标识与 `session_id` 计数。
- 计入来源不变：`afterglow`、`serendipity`、`longing`、`later` 的 `proactive` 意图；`cancelled` / `failed` 不计。
- 豁免规则不变：`return` 回接、`workflow`、绑定 `profile` 的计划、`scheduled_admin`、`watch` 均不扣额。
- 两层都满足才放行；任一层用尽时，第 1 步不产生想念候选。

## 五、对话调整面

- `maisya_shape(action="settings")`：
  - 接受 `heartbeat_mode`，同时容错 `关 / 克制 / 活泼 / off / gentle / lively / on`（`on` → `gentle`）；
  - 接受 `per_chat_daily_proactive_limit` 与两个高级覆盖；
  - `heartbeat_enabled` 按第二节的兼容规则映射。
- `maisya_shape(action="overview")` 的心跳块：
  - 档位；
  - 实际生效状态：`关闭` / `只会想念（未填逛逛方向）` / `想念 + 逛逛`；
  - 基准间隔与想念阈值（标明是否为覆盖值）；
  - 下次跳动时间；
  - 今日额度剩余（全局 / 本会话）；
  - 最近 5 次跳动结果。
- 管理员引导语（`before_planner`）：把字段清单改为「说法 → 旋钮」对照，一行写清：
  - 更主动 / 更安静 / 别主动 → `heartbeat_mode`；
  - 想逛什么 → 写 `HEARTBEAT.md` 的「## 自主探索方向」；
  - 某个群别打扰 → `chat_proactive_levels`；
  - 次数 → 两个额度字段。
- 打开心跳但探索方向为空时，不自动代填。概览会明确报出「只会想念」，由 MaiBot 视语境询问用户或替用户写入方向。

## 六、WebUI

- **设置 → 心跳与运行**：
  - 开关改为「关 / 克制 / 活泼」三段选择；
  - 间隔输入框改为「高级：间隔覆盖（0 = 跟随档位）」；
  - 新增单会话每日上限；
  - 状态文案改为第五节的实际生效状态。
- **手账页**：状态标签按档位与方向显示。
- **现场页**：展示最近心跳记录。可作为第二阶段交付。

## 七、迁移

存量 `settings.json` / `config.toml` 若缺少 `heartbeat_mode` 键且属于完整落盘（含 `heartbeat_enabled` 键，或同时含 `plugin` 与 `heartbeat_profile` 键，覆盖旧 `v0.3.0` 升级前落盘），视为旧版配置：

- `heartbeat_mode`：`longing_quiet_hours > 0` 时设为 `gentle`（保留该值作为想念阈值覆盖），否则设为 `off`；
- `heartbeat_interval_minutes`：重置为 `0`（旧默认 `60` 是落盘默认值，不代表用户意图）；
- `daily_proactive_limit`：旧值为 `1`（旧默认）时改为新默认 `3`，其他值原样保留为全局总量；
- `heartbeat_enabled`：忽略。

## 八、边界（不变式）

- 心跳不直接发消息。所有触达都经意图管线和三道社交闸，最终由目标会话 `planner` 决定是否开口。
- 便宜判断的输入不含任何会话私有备忘或聊天原文；自身探索线程继续只围绕公开主题，跨会话隐私隔离不变。
- `afterglow`、`later`、`watch`、`workflow`、`return` 的行为不受档位影响。

## 十、实现核对记录（与初稿的两处细化）

1. **想念候选不含显示名**：宿主与插件的 `session_routes` 路由表只记录 `<platform>:<group|private>:<id>` 与 32 位 `session_id` 映射，不保存群名或对方昵称；因此便宜判断输入的想念候选仅传递匿名 `ref`（`c1..cN`）、会话类型（`group` / `private`）与安静小时数 `silent_hours`，进一步收窄上下文暴露面。
2. **无由头跳动也记入 `heartbeat_ticks`**：当探索方向为空且无满足条件的想念候选时，代码零模型调用直接推迟下次 `_heartbeat_next_at`（不写入 `social_state` 冷却），同时在 `heartbeat_ticks` 写入一条 `outcome="ok:no_reason"` 记录，使管理台概览与「现场」页可清晰观测到心跳仍在按档位静默巡检。
