# 管理台与接入

> 本文档描述 `Maisya v0.3` 的四页双主题 WebUI、5 步首次安装引导、管理员直通与跨会话管理，以及连接器（`services.json`）和条件盯梢（Watch）的接入规范。

---

## 一、四页双主题玻璃盒管理台

Maisya 通过 [`webui.json`](../webui.json) v2 声明单一宿主工作区页面入口（`id = "now"`，`entry = "webui/now.html"`，`layout = "viewport"`），复用 MaiBot 原生登录态、不新开任何端口，并在单页内部提供 **4 页视图** 与 **双主题体系**：

- **外观主题（`ui_style`）**：
  - `millennium`（默认）：契合 MaiBot 宿主的 0px 锐边千禧机械质感；
  - `modern`：现代极简留白主题（向后自动兼容旧配置值 `"maiwork"`）；
  - `auto`：自动跟随宿主风格切换。
- **四个页面（桌面顶栏 / 移动端 4 栏底栏 `.ms-mob-dock`）**：

| 页面 | 核心职责与交互 |
|---|---|
| **现场（`now`）** | 左栏展示**「预定与盯梢（`schedule` / `watch` 任务、下次触发时间、上次检查状态，支持暂停/立即运行/取消）」**与**「活动时间线（按会话/档案过滤与一键清理废记录）」**；右栏采用垂直步骤时间线（点击单步查看脱敏后的调用参数、命令与输出），默认联动展示结果摘要、附件与 **上下文/Token 方块图（Treemap）**，运行中支持直接发送补充/转向（`steer`）、停止（`stop -> idle`）或对 `waiting` 风险挂起执行审批 |
| **档案（`profiles`）** | 围绕开箱全能 `default` 主档案与按需定制档案，采用 Hermes 式渐进表单：首屏只展示标识、名称、一句话描述、可用范围（`everyone` / `admins` / `listed`）与启用开关；展开 `⌄ 高级` 切换 `常规 \| 能力`，提供模型与顺次 `fallback`、会话模式（常驻主线 `persistent` / 按事 `ephemeral` + 一键归档重开）、`PROFILE.md`（限 `150` 行，留空可自动生成）与**5 大工具集 / 技能 / 连接器**开关卡片，以及单档案 `.zip` 导入导出；**移动端窄屏（`<= 760px` 头部 / `<= 720px` 全局断点）保留无框横向游动像素鱼轮播开关（`#ab-mob-head` / `#mob-role-carousel` / `#ab-mob-role-card1`）** |
| **资料库（`library`）** | 主视图为产物画廊（全部 / 页面与卡片 / 图像海报 / 文档与代码 / 结论摘要），联动预览与源码检视；侧栏底部固定 `#lib-fs-entry` 入口打开受管系统文件树，集中浏览并安全编辑/回滚各会话 `MEMORY.md`、7 天 `JOURNAL.md`、`HEARTBEAT.md`、`skills/`、`profiles/` 与持续工作区文件 |
| **设置（`settings`）** | 收敛为 4 个干净区块：**① 会话开关**（`plugin.enabled` 总开关、管理员私聊直通标识与 `<platform>:<group\|private>:<id>` 条目增删白名单）；**② 权限与管理员**（只读继承 `host_admins` 与可增删 `plugin_admins`、执行确认策略 `ask_risky / autonomous / always_ask`、已记住授权 `permission_grants` 列表与撤销、「重新打开启动引导」按钮）；**③ 安全存储**（仅展示 `vault_meta.json` 非敏感索引列表与增删）；**④ 基础运行**（全局 `default_model`、`daily_proactive_limit`、免打扰时段、可选 `DockerRunner` 开关与双主题切换） |

### WebUI 架构与构建约束

- **宿主通信与并发契约**：全部操作经宿主 `window.maibot` 调用 3 组查询与 3 组写操作：
  - 查询：`snapshot` -> `maisya_now`、`event` -> `maisya_event`、`read` -> `maisya_manage_read`
  - 操作：`note` -> `maisya_note`、`stop` -> `maisya_stop`、`write` -> `maisya_manage_write`
  - 现场页使用单路游标串行轮询，为写入操作预留并发槽位（每插件峰值并发 `<= 2`，单次 RPC 限时 `10s`）。
- **CSP 安全与构建命令**：编译产物 [`webui/now.html`](../webui/now.html) 遵守 `connect-src 'none'`（零外链、零 `<img>`、零 `<iframe>`、零 `localStorage`、零 `transition: all`）。修改 [`webui/now.html.in`](../webui/now.html.in)、[`webui/management.html.in`](../webui/management.html.in)、[`webui/fragments/`](../webui/fragments/)、[`webui/millennium.css`](../webui/millennium.css)、[`webui/icons.js`](../webui/icons.js) 或 [`webui/fish.js`](../webui/fish.js) 后，必须运行：
  ```bash
  python3 webui/build.py && python3 webui/build.py --check
  ```

## 二、5 步首次安装引导与能力就绪清单

首次打开管理台时，[`maisya/onboarding.py`](../maisya/onboarding.py) 根据持久化文件 `<宿主根>/data/maisya/onboarding.json`（`0600`）与运行态判断是否弹出 **5 步全屏引导浮层**（存量活跃用户升级时静默免打扰，可在「设置 → 权限与管理员」随时点击重开）：

1. **五步固定流转（`STEPS`）**：`hello`（说明与原理）→ `admins`（展示只读宿主管理员 + 从近期私聊候选点选或手动补充插件管理员）→ `chats`（开启 `plugin.enabled` 与按需勾选会话）→ `runtime`（选 `default_model`、确认 `permission_mode` 门槛、切换工作台主题，支持 8 秒限时无秘钥模型探针 `onboarding_verify_model`）→ `done`（展示 7 项只读就绪清单与开箱试跑提示）。
2. **状态枚举（`STATUSES`）**：`"not_started"` / `"in_progress"` / `"completed"` / `"skipped"`。
3. **防竞态票据**：每次重新开启生成新 `run_id` 与递增 `sequence`，写操作 `onboarding_advance` / `onboarding_complete` / `onboarding_skip` / `onboarding_verify_model` 校验票据防止旧请求回退步骤；模型探测严格剥离并过滤任何 `api_key`、`base_url`、`token` 或 `secret`。
4. **7 项只读就绪清单（`items`）**：`admins`（必填）、`chats`（必填）、`models`（必填）、`default_profile`、`toolsets_mcp`、`runtime`、`safety`。

## 三、三路配置与管理员跨会话管理

- **三路配置合并**：运行态配置存放在 `<宿主根>/data/maisya/settings.json`，并在 `settings.base.json` 记录上次与 `config.toml` 对齐的基线。重载或升级时，仅在 `config.toml` 中新改动的字段会同步覆盖运行时，用户在 WebUI 或对话 `maisya_shape` 中调整过的字段保留，同时在 `settings_history.json` 保留历史供回滚。
- **双源管理员与私聊直通**：
  - 有效管理员 = `宿主 plugin.permission（只读继承） ∪ 插件 Settings.admins（支持引导/设置页/对话增删）`；
  - 规范化仅小写平台名、完整保留 `user_id` 大小写（适配 QQ 官方敏感 OpenID）；修改 `admins` 时禁止删空有效管理员集合或移除发起人自身（防自锁死）；
  - 当 `plugin.enabled = true` 时，**已核验管理员私聊无需将私聊流列入 `enabled_chats` 即可直通全部工具与跨群指令**。
- **标准会话格式**：统一使用 `<platform>:<group|private>:<id>`（如 `qq:group:100246809`、`qq:private:10001`、Telegram 话题 `telegram:group:-100123456::tg-topic::mt=12`），后台经 `session_routes` 与 `chat_aliases` 自动兼容解析 32 位哈希 `session_id` 及群名。

## 四、单档案 `.zip` 导入导出

`v0.3` 已移除繁重的「配方模板（Recipe）」子系统与远端 URL 拉取通道，简化为单档案文件夹直打 `.zip` 包（`profile_export_zip` / `profile_import_zip`）：

- **导出包含**：`PROFILE.md`、`profile.toml`（自动剥离本机 `allow_chats` / `allow_users` 与 `secrets` 绑定字段）、可选 `NOTES.md` 与 `preset/` 目录素材；导出前强制扫描 `vault.contains_secret` 与常见密钥正则，命中即阻断导出。
- **导入处理**：校验压缩包路径防穿越与大小上限；支持同名档案覆盖更新（保留本机白名单与已有工作区）或另存为新档案标识。

## 五、能力范围与真实发言人核验

在自定义档案 `profile.toml` 中设置作用域：

```toml
access = "listed"                      # everyone | admins | listed
allow_users = ["qq:10001"]
allow_chats = ["qq:group:100246809"]
```

- 同时配置 `allow_users` 与 `allow_chats` 时取交集；
- `access = "admins"` 档案、高风险确认审批（`approve`）、`target_chat` 跨群调度及受限线程检索均按真实 `source_msg_id` 反查 `trusted_sources` 验权（排除插件代投消息；宿主攒批后的 `context.user_id` 不授予权限）。

## 六、凭据保险箱与连接器登记（`abilities/services.json`）

### 1. 凭据保险箱（`/vault`）

- 录入方式：在 WebUI「设置 → 安全存储」或由核验过的管理员在私聊发送 `/vault set <句柄名> <密钥>`（进入插件前立即清洗聊天文本，不把明文写进对话历史）。
- 存储形式：使用 `Fernet` 加密并以 `0600` 权限存放在 `<宿主根>/data/maisya/vault/`；同步生成非敏感元数据目录 [`vault_meta.json`](../maisya/vault.py)（含句柄、类别、域名、备注），管理台与线程上下文仅可见句柄名录，所有输出经 `vault.redact()` 脱敏。

### 2. 外部连接器：`abilities/services.json`

`v0.3` 的 `services.json` 收敛为 **4 个连接器节点**（已移除旧版静态命令 `templates` 节点，命令行与脚本统一走 `HostWorkspaceRunner` / `DockerRunner`）：

```json
{
  "servers": {
    "platform_files": {
      "command": ["/opt/maisya-services/bin/python", "/opt/maisya-services/reader.py"],
      "tools": ["read_file"],
      "readonly": true,
      "access": "everyone",
      "credentials": {"PLATFORM_TOKEN": "platform_token"}
    }
  },
  "apis": {
    "weather": {
      "plugin_id": "other.plugin",
      "api_name": "get_weather",
      "description": "查询指定城市天气",
      "readonly": true,
      "access": "everyone",
      "schema": {
        "type": "object",
        "properties": {"city": {"type": "string", "minLength": 1}},
        "required": ["city"],
        "additionalProperties": false
      }
    }
  },
  "web": {
    "search": {"api": "search_api"},
    "fetch": {"service": "web_mcp", "tool": "fetch_page"},
    "providers": {}
  },
  "inputs": {
    "qq": {"service": "platform_files", "tool": "read_file"}
  }
}
```

- **`servers`（stdio MCP）**：`command` 须使用绝对路径（拒绝 UNC 路径）；启动受控子进程时仅透传最小必要系统环境变量并按配置注入保险箱句柄，Linux 环境额外支持降权运行。`readonly = false` / `access = "admins"` 的写 MCP 仅对管理员角色及已核验管理员轮次开放。
- **`apis`（跨插件 `@API`）**：底层调用宿主 `api.list` / `api.get` / `api.call`，普通会话仅开放 `readonly = true` 接口，管理员档案授权后可调用可写接口。
- **`web`（自定义联网源）**：在 `web_provider = "auto"` 下当宿主统一联网未开启时作为回退源，或按 `web:<别名>` 固定指定。
- **`inputs`（平台文件实体读取器）**：按平台绑定 `{message_id, file_ref}` 只读转换 MCP 工具，将二进制资源写入线程只读 `in/` 目录。

## 七、条件盯梢（Watch）替代历史 Webhook

为消除高维护成本与额外签名转发复杂度，`v0.3` **已移除** `webhooks.json`、`maisya/incoming.py` 与外部 `maisya_incoming_event` 接口，改为由原生 `maisya_later(action="schedule", mode="watch", ...)` + `Pulse` 统一承担持续监测：

- **工作方式**：安排周期性静默巡检（`every_seconds >= 300`）并填写自然语言触发条件 `condition`（例如监控某接口状态、某仓库新版本或特定群内公告）。
- **静默不刷屏**：巡检到期时在后台独立工作区注入 `<watch_contract>` 与近 3 次检查摘要 `<previous_runs>` 对比基线；若未满足条件，线程仅输出 `[WATCH:NO_CHANGE]`，只刷新 `last_checked_at`，**不唤醒群聊、不发任何消息、也不消耗每日主动额度**。
- **命中才汇报**：一旦满足 `condition`，自动产出结论与可选图卡附件并按权限路由汇报（管理员安排的巡检受 `scheduled_admin` 保护，非管理员不可取消）；在管理台「现场 → 预定与盯梢」支持查看最近检查与触发状态，以及随时暂停（`intent_pause`）、恢复（`intent_resume`）、立即巡检一次（`intent_run_now`）或取消。
