# 管理台与接入

五页管理台与对应 API 通过本地单测（含 Playwright Chromium 浏览器 UI 测试）、真实宿主 SDK 隔离契约、隔离实模第三方联网（`google-search-plugin` EXA 实网搜索 + 网页正文提取）冒烟及独立 Docker/runsc 运行时验收。真实平台群文件读取与指定测试群外发仍在联调前受线上红线约束。

## 五个页面

| 页面 | 当前可用操作 |
|---|---|
| 现场 | 线程列表、可选「唤醒角色」旁路入口、步骤过程、角色与技能/手账备忘/输入/推理结论/工具调用五段上下文构成、当前结果、待唤醒意图提示、勾选立即转向的「引导」与停止 |
| 产物 | 集中浏览与检视所有已声明附件/图片（支持基于 CSS 背景图与 Blob/Base64 的安全预览）、工作区 `out/` 成品（安全阅读器 + 源码视图 + 一键复制）、已完成线程结论与出处链接，以及持续工作区目录树浏览 |
| 能力 | 围绕 `SKILL.md` 技能库管理（搜索筛选、新建/复制/导入 Markdown/复制全文、预设技能一键重置、YAML frontmatter 可视化编辑、一键勾选装配给各角色，含开箱 `source-checking`、`ongoing-workspace` 与 `news-digest`）以及角色（`profile`）管理（一键开启/停用 `enabled` 开关，预设 `digest` 默认停用；编辑/克隆/删除角色说明、TOML 配置、方法笔记；历史与回滚、角色包导入导出与宿主发现只读参考） |

| 设置 | 会话范围、活动预算、可定制 `web_provider`（下拉与自由输入框）、`daily_proactive_limit` / `heartbeat_interval_minutes` / `heartbeat_profile`、默认与会话独立主动级别（`chat_proactive_levels`）、熟识账号（`acquaintance_users`）、想念触发静默阈值（`longing_quiet_hours`）、睡眠与沙箱参数、凭据录入/删除、MCP/模板/跨插件 API/联网服务登记、管理员定时/周期工作流调度（含一键填入 `digest` 资讯简报预设）、事件通道、执行状态（含联网来源与自定义 provider） |

页面全部内联，通过宿主 `window.maibot` 调用静态 API。管理操作复用宿主登录，API 不向其他插件公开；签名事件 API 单独开放，但仍验证通道签名。页面不发外部网络请求，查询与操作串行进行；现场页单路轮询，为用户操作保留第二个并发槽。

管理员名册继承宿主。管理页设置保存在插件目录外的 `data/maisya/settings.json`，并在 `data/maisya/settings.base.json` 记录上次同步的 `config.toml` 基线：插件重载或版本化配置更新时，对 `settings.base.json`、`settings.json` 与 `config.toml` 执行三路合并——管理台单独改过的字段在 `config.toml` 未变动时保留，而直接在 `config.toml` 修改的字段在重启或更新后立即生效。数据库、凭据、档案、记忆与工作区统一留在外部数据目录。

容器沙箱支持在 `[sandbox]` 配置并发容器上限 `max_concurrent`（默认 `2`，范围 `1..8`）；对应默认镜像 `maisya-sandbox:py313` 由仓库根目录的 `sandbox/Dockerfile` 与 `sandbox/build_image.sh` 提供（默认 dry-run，`--execute` 执行构建）。联网搜索来源可通过 `web_provider` 配置（默认 `"auto"`）：优先调用宿主统一联网 `web.search` / `web.fetch`；当宿主明确提示统一联网未启用/未配置时，自动回退到 `services.json["web"]`（只读 MCP 或跨插件只读 `@API`）或宿主已启用的第三方联网搜索插件（`xxxxx7258.google-search-plugin`）。也可在设置页手动固定或在角色（`profile`）配置 `profile.toml` 中按角色覆盖为 `host`、`google_search_plugin`、`mcp`、`plugin_api`、`mcp:<服务>`、`plugin_api:<接口>`、`plugin:<插件ID>` 或 `web:<自定义别名>`。

宿主插件列表决定是否加载插件；管理页开关控制 Maisya 活动。卸载时会取消并等待管理请求与事件接收收束，再清理线程和执行器。前端共用源码为 `webui/management.html.in` 与 `webui/fragments/`，运行 `python3 webui/build.py` 输出五个独立自包含页面（`now.html` 及四个管理页）；`--check` 核对产物，安装使用时不需要构建。

## 编辑与角色包

保存和回滚使用当前版本号。版本冲突不会覆盖正文；“读取最新”把旧草稿留在下方，管理员核对后再保存。切换技能、角色或手账文档时，本页保留未保存草稿。

导出的角色包包括角色说明、配置、方法笔记、预设资产与绑定技能。技能随包放在该角色的 `preset/skills/`，不覆盖本机的全局技能库；已有同名全局技能优先使用。含服务、私有凭据或指定范围的导入角色包默认 `bound=false`，核对本机绑定后才启用。

宿主 iframe 只有 `allow-scripts`，禁止直接下载文件。因此导出提供可复制的包文本，可在另一份 Maisya 中粘贴导入；已有 ZIP 可以通过文件选择器导入。API 按 24 KiB 分块传输，最多同时保留四份传输、五分钟过期；ZIP 最大 8 MiB，解压后总计最大 16 MiB、最多 256 项。凭据值不进入角色包。

## 自身活动与主动性

```json
{"action":"start","profile":"scout","owner":"self","workspace":"海岸旅行","message":"沿着海岸探索一个有意思的地点"}
```

自身活动统一使用 `self` 归属与命名空间，可以从不同启用会话续接同一个线程。普通 `send`、显式 `steer`、`stop`、检索和 Pulse 续接均可使用。`share` 把结果交到当前会话，准确链接与已声明附件走原生交付（若包含 `file` 附件，则在主表达之后拆分为独立 `send.hybrid` 消息跟发）；去重按结果版本和目标会话分别记录。

自身活动只调度公开、无私有凭据、无指定用户/会话限制的角色（`profile`）。原会话引用和 `from_threads` 不可带入自身活动；已知会话记忆片段及个人/主机标识也会在输入检查时拒绝。会话关系继续留在原会话，自身公开结果进入七天近况，完整经历保留在线程中。自身公开探索线程可在内部通过 `thread_later(kind="serendipity", share_reason=...)` 提议偶遇分享，由 Pulse 自动筛选 `chat_proactive_levels` 为 `lively` 且会话 `MEMORY.md` 关键词投缘的启用会话安排唤醒；否则只做常规 `silent` 线程延续，不直接向群发消息。

主动度同时支持全局 `proactive_level`（`quiet` / `care` / `lively`）与按会话覆盖的 `chat_proactive_levels`（整份映射原子保存）：
- `quiet`：拦截所有主动搭话与偶遇；仅当全部会话皆为 `quiet` 时停跑 `HEARTBEAT.md` 自身定期探索。
- `care`（默认）：放行 `afterglow`、`longing`、`later`，拦截 `serendipity` 偶遇。
- `lively`：全部放行，允许承接自身探索提议的 `serendipity`。
- **熟人边界与久违想念**：群聊需出现过真实非插件代投消息；冷私聊默认不主动戳陌生账号，需已有真人非代投往来、属于宿主管理员或命中 `acquaintance_users`（`platform:user_id`）。规则化 `_longing` 在醒着且今日普通主动额度未用完时，筛选至少 3 条真人消息、最近真人互动超过 `longing_quiet_hours`（默认 `72` 小时，设 `0` 关闭）且未上未回锁、满足 7 天冷却的熟识会话生成一次 `longing` 意图，并在 `proactive` 唤醒时注入 `HEARTBEAT.md` 的脾性基线（`<maisya_temperament>`）与绑定线程结果摘要（`<maisya_thread_result>`）。

## 指定可用范围

在角色配置（`profile.toml`）中设置：

```toml
access = "listed"
allow_users = ["qq:123456789"]
allow_chats = ["会话编号"]
```

两类列表同时存在时取交集。用户列表核验真实发言人，平台使用小写、用户 ID 保持原样；攒批后的上下文 `user_id` 不授予权限。仅限制会话、没有用户列表的普通角色可在该会话自主调用。管理员角色仍需要真实管理员消息。

限制在请求前的角色展示、启动/续接/停止、检索、引用输入和模型/工具执行边界检查。检索受限线程时提供 `source_msg_id`。权限变化后旧线程不能沿用原来的宽权限；私有工作区也不能通过修改角色范围向另一批用户开放。

## MCP、跨插件只读 `@API` 与平台文件

先在保险箱录入凭据，再在服务登记（`abilities/services.json`）中填写句柄。程序及参数由管理员固定登记，只在 Agent 调用时启动。Linux MCP worker 降权运行，程序和依赖须允许该运行账户读取；秘密由执行边界注入，不交给模型。

如需在探索或工具执行期间只读调用其他插件公开的 `@API`（如读取天气、动态等），可在 `services.json` 的 `"apis"` 节点登记白名单，并在角色的 `profile.toml` 中设置 `tools = [..., "plugin_api"]` 与 `apis = ["接口别名"]`：

```json
{
  "servers": {},
  "templates": {},
  "apis": {
    "weather": {
      "plugin_id": "other.plugin",
      "api_name": "get_weather",
      "description": "查询指定城市天气",
      "readonly": true,
      "access": "everyone",
      "schema": {
        "type": "object",
        "properties": {"city": {"type": "string", "minLength": 1}},
        "required": ["city"],
        "additionalProperties": false
      }
    }
  }
}
```

默认开放给普通用户的 API 须声明 `readonly = true`；`access = "admins"` 且配置了 `readonly = false` 的可写接口与 MCP 服务，仅在 `admins` 角色且核验本次管理员授权（真实管理员消息、控制台或管理员定时任务）时放行。底层通过宿主 `api.list` / `api.get` / `api.call` 能力执行，兼容 SDK 自动解包 `result` 字段（含合法返回 `None`/`0`/`[]`），返回前统一经保险箱脱敏。

若要将 `web_search` / `web_fetch` 显式、回退或按别名（`web:<别名>`）指向管理员登记的 MCP / 跨插件 `@API`，可在 `services.json` 增加可选 `"web"` 节点，并在 `"providers"` 中定义 `arg_map` 与 `defaults` 字段映射（不传参或只读工具可设 `readonly = true`）：

```json
{
  "web": {
    "search": {"api": "search_api"},
    "fetch": {"service": "web_mcp", "tool": "fetch_page"},
    "providers": {
      "my_search": {
        "kind": "plugin_api",
        "target": "third.search.run",
        "arg_map": {"query": "q", "limit": "n"},
        "defaults": {"lang": "zh-CN"}
      }
    }
  }
}
```

平台仅返回 `file_ref` 时，可以登记可信文件读取器：

```json
{
  "servers": {
    "platform_files": {
      "command": ["/opt/maisya-services/bin/python", "/opt/maisya-services/reader.py"],
      "tools": ["read_file"],
      "readonly": true,
      "credentials": {"PLATFORM_TOKEN": "platform_token"}
    }
  },
  "templates": {},
  "inputs": {"qq": {"service": "platform_files", "tool": "read_file"}}
}
```

对应 `maker` 角色需要授权 `mcp=["platform_files"]` 和 `mcp_call`。读取器接收 `{message_id,file_ref}`；`file_ref` 原样来自宿主原会话消息，不作为宿主文件路径解析。工具应返回单个 MCP 二进制资源：

```json
{"content":[{"type":"resource","resource":{"uri":"file:///input.csv","mimeType":"text/csv","blob":"文件字节的base64"}}]}
```

文件实体进入该线程只读 `in/`，模型只获得路径和来源；输入不会自动变成结果附件。没有配置读取器时，返回具体缺失原因。测试已实际启动 stdio 读取器验证这条链；上述协议不预设任何平台适配器的鉴权和下载 API，真实平台读取程序与凭据需按实际环境登记。

## 外部事件

在保险箱录入签名密钥，再登记固定通道：

```json
{
  "news": {"target": "chat:会话编号", "kind": "proactive", "secret_handle": "event_key"},
  "digest": {"target": "chat:会话编号", "kind": "proactive", "profile": "scout", "workspace": "daily_digest", "secret_handle": "digest_key"}
}
```

`proactive` 经主动度、睡眠、熟人、额度与未回不连戳检查。`silent` 若绑定已有公开线程的 `thread_id`，到期后只续跑该线程。

通道也可直接指定自主角色 `profile`（不可与 `thread_id` 同时填写，且该角色须设 `autonomous = true`）以及可选 `workspace`：收到合法签名事件后在并发锁内先检查 `event_key` + `event_digest` 去重，随后立即开启自主线程整理事件内容；当 `kind == "proactive"` 时写入带 `wait_thread=true` 的意图，若线程仍在运行则每次顺延 `5` 秒等待收尾，线程完成后携带 `<maisya_thread_result>` 与 `<external_event>` 由 Pulse 决定是否向目标会话自然提起；当 `kind == "silent"` 时则只把整理结论留在工作区与线程历史中，不额外再发送重复续跑消息。事件内容本身均不能覆盖目标、管理员来源或角色权限。

接收 API 为 `maisya_incoming_event(channel,event_id,timestamp,payload,signature)`，也绑定在设置页 `incoming_event` action。HTTP 路径为宿主已有的：

```text
POST /api/webui/plugins/runtime/webui/chartyr.maisya/settings/actions/incoming_event
Cookie: maibot_session=<宿主登录凭据>
Content-Type: application/json
```

请求体为 `{"args":{...接收API的五个参数...}}`。`payload` 是 JSON 字符串，只接受 `reason` 和可选 `data`；最多 16 KiB。时间为 Unix 秒，与接收端相差不超过五分钟。签名算法：

```python
envelope = {
    "channel": channel,
    "event_id": event_id,
    "timestamp": timestamp,
    "payload": payload,
}
canonical = json.dumps(envelope, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
signature = hmac.new(secret.encode(), canonical.encode(), hashlib.sha256).hexdigest()
```

密钥由调用方自己的安全存储提供。相同通道和事件编号重复投递返回同一个 Intent；改动内容后重用编号会被拒绝。回执与 Intent 在同一事务提交，重启不会把同一事件重新创建一次。

该入口继续要求宿主认证，不新开端口；无法携带宿主认证的第三方平台需要可信转发器接入。当前已验证 API 签名、时效、去重与 Intent 转换，真实外部 HTTP 投递尚未运行。
