# 管理台与接入

> 本文档描述 `Maisya` 的五页双主题 WebUI、5 步首次安装引导、管理员直通与跨会话管理，以及「外部连接」（MCP 粘贴 JSON / HTTP / stdio 直填密码 + 跨插件 `@API`）和条件盯梢（Watch）的接入规范。

---

## 一、五页双主题玻璃盒管理台

Maisya 通过 [`webui.json`](../webui.json) v2 声明单一宿主工作区页面入口（`id = "now"`，`entry = "webui/now.html"`，`layout = "viewport"`），复用 MaiBot 原生登录态、不新开任何端口，并在单页内部提供 **5 页视图（能力页内含 角色 \| 技能 \| 外部连接 三个子栏）** 与 **双主题体系**：

- **外观主题（`ui_style`）**：
  - `millennium`（默认）：契合 MaiBot 宿主的 0px 锐边千禧机械质感；
  - `modern`：现代极简留白主题（向后自动兼容旧配置值 `"maiwork"`）；
  - `auto`：自动跟随宿主风格切换。
- **五个页面（桌面顶栏 / 移动端底栏 `.ms-mob-dock`）**：

| 页面 | 核心职责与交互 |
|---|---|
| **现场（`now`）** | 左栏展示**「预定与盯梢（`schedule` / `watch` 任务）」**与**「活动时间线（按会话/角色过滤，发起临时线程支持直接下拉选择角色、会话与工作区）」**；右栏采用垂直步骤时间线联动上下文 Token 方块图（Treemap），支持运行中补充/转向（`steer`）、停止（`stop -> idle`）或风险确认 |
| **产物（`library`）** | 集中预览线程产出的网页报告、图卡、文档、代码与结论摘要；按类型统计与来源会话过滤，支持网页安全预览与原码切换 |
| **能力（`abilities`）** | 包含三个子栏：**① 角色**（内置 `default` 全能 / `scout` 查证 / `digest` 资讯与自定义角色；展开可调模型回退链、技能/系统工具/外部连接开关、独立 `profiles/<id>/MEMORY.md` 与 `NOTES.md`，以及三层脱敏 `.maisya.zip` 打包导出/预览/导入）；**② 技能**（自动复盘新技能草稿预览确认、近期活动手动提炼、正文章节与 `references/` 等附属参考文件编辑）；**③ 外部连接**（MCP 连接中心：支持粘贴 `mcpServers` JSON、切换本机程序 stdio / 远程网址 HTTP、**直接填写环境变量/请求头密码无需先存保险箱**、一键 `测试连接并获取工具` 勾选可用工具，以及一键登记宿主发现的跨插件 `@API`） |
| **手账（`memory`）** | 顶部状态条直观展示今日主动搭话用量、免打扰时段与未回不连戳锁；集中浏览、编辑与版本回滚各会话 `MEMORY.md`、7 天自身近况 `JOURNAL.md`、闲暇 `HEARTBEAT.md`，以及可一键撤回的自动复盘经验回执 |
| **设置（`settings`）** | 直观收敛：**① 会话开关**（总开关、管理员直通提示、流白名单条目管理）；**② 权限与管理员**；**③ 密码保险箱**（可选便利功能：仅存「别名 + 密码」，点「查看」只显示别名与保存日期、绝不回显密码，平时用户也可直接在聊天发临时密码做事无需先存）；**④ 常规心跳、免打扰、主题与沙箱开关**（精细微调留白给管理员在对话中让 MaiBot 调整） |

### WebUI 架构与构建约束

- **宿主通信与并发契约**：全部操作经宿主 `window.maibot` 调用 3 组查询与 3 组写操作：
  - 查询：`snapshot` -> `maisya_now`、`event` -> `maisya_event`、`read` -> `maisya_manage_read`
  - 操作：`note` -> `maisya_note`、`stop` -> `maisya_stop`、`write` -> `maisya_manage_write`
  - 现场页使用单路游标串行轮询，为写入操作预留并发槽位（每插件峰值并发 `<= 2`，单次 RPC 限时 `10s`）。
- **CSP 安全与构建命令**：编译产物 [`webui/now.html`](../webui/now.html) 遵守 `connect-src 'none'`（零外链、零 `<img>`、零 `<iframe>`、零 `localStorage`、零 `transition: all`）。修改 [`webui/now.html.in`](../webui/now.html.in)、[`webui/management.html.in`](../webui/management.html.in)、[`webui/fragments/`](../webui/fragments/)、[`webui/millennium.css`](../webui/millennium.css)、[`webui/icons.js`](../webui/icons.js) 或 [`webui/fish.js`](../webui/fish.js) 后，必须运行：
  ```bash
  python3 webui/build.py && python3 webui/build.py --check
  ```

## 二、5 步首次安装引导与能力就绪清单

首次打开管理台时，[`maisya/onboarding.py`](../maisya/onboarding.py) 根据持久化文件 `<宿主根>/data/maisya/onboarding.json`（`0600`）与运行态判断是否弹出 **5 步全屏引导浮层**（存量活跃用户升级时静默免打扰，可在「设置 → 权限与管理员」随时点击重开）：

1. **五步固定流转（`STEPS`）**：`hello`（说明与原理）→ `admins`（展示只读宿主管理员 + 从近期私聊候选点选或手动补充插件管理员）→ `chats`（开启 `plugin.enabled` 与按需勾选会话）→ `runtime`（选 `default_model`、确认 `permission_mode` 门槛、切换工作台主题，支持 8 秒限时无秘钥模型探针 `onboarding_verify_model`）→ `done`（展示 7 项只读就绪清单与开箱试跑提示）。
2. **状态枚举（`STATUSES`）**：`"not_started"` / `"in_progress"` / `"completed"` / `"skipped"`。
3. **防竞态票据**：每次重新开启生成新 `run_id` 与递增 `sequence`，写操作 `onboarding_advance` / `onboarding_complete` / `onboarding_skip` / `onboarding_verify_model` 校验票据防止旧请求回退步骤；模型探测严格剥离并过滤任何 `api_key`、`base_url`、`token` 或 `secret`。
4. **7 项只读就绪清单（`items`）**：`admins`（必填）、`chats`（必填）、`models`（必填）、`default_profile`、`toolsets_mcp`、`runtime`、`safety`。

## 三、三路配置与管理员跨会话管理

- **三路配置合并**：运行态配置存放在 `<宿主根>/data/maisya/settings.json`，并在 `settings.base.json` 记录上次与 `config.toml` 对齐的基线。重载或升级时，仅在 `config.toml` 中新改动的字段会同步覆盖运行时，用户在 WebUI 或对话 `maisya_shape` 中调整过的字段保留，同时在 `settings_history.json` 保留历史供回滚。
- **双源管理员与私聊直通**：
  - 有效管理员 = `宿主 plugin.permission（只读继承） ∪ 插件 Settings.admins（支持引导/设置页/对话增删）`；
  - 规范化仅小写平台名、完整保留 `user_id` 大小写（适配 QQ 官方敏感 OpenID）；修改 `admins` 时禁止删空有效管理员集合或移除发起人自身（防自锁死）；
  - 当 `plugin.enabled = true` 时，**已核验管理员私聊无需将私聊流列入 `enabled_chats` 即可直通全部工具与跨群指令**。
- **标准会话格式**：统一使用 `<platform>:<group|private>:<id>`（如 `qq:group:100246809`、`qq:private:10001`、Telegram 话题 `telegram:group:-100123456::tg-topic::mt=12`），后台经 `session_routes` 与 `chat_aliases` 自动兼容解析 32 位哈希 `session_id` 及群名。

## 四、三层打包导出预览与 `.maisya.zip` 分享（无虚假内链）

Maisya 作为用户自部署插件不依赖中心转发服务器，因此**不生成虚构的 `maisya://` 分享链接**，统一使用本地 `.maisya.zip` 压缩包与公开 `https://` 压缩包直链（服务端带固定 IP 防 SSRF 校验）：

- **打包导出预览（`profile` / `capability_pack` / `template`）**：弹窗与导出前均先展示脱敏清单（是否包含身份设定、技能数、脱敏日程数与依赖的凭据别名）；自动剥离本地 `allow_chats`、`allow_users`、群号/用户 ID、宿主机私密路径与任何 Vault / MCP 内联密钥。
- **导入与推荐定时落地**：支持本地 `.zip` 上传（大图自动分块续传）或公开 `https://` 直链拉取预览；支持覆盖更新或另存为新角色，如包内附带推荐定时任务，可按需当场勾选绑定到本地目标会话激活。

## 五、能力范围与真实发言人核验

在自定义档案 `profile.toml` 中设置作用域：

```toml
access = "listed"                      # everyone | admins | listed
allow_users = ["qq:10001"]
allow_chats = ["qq:group:100246809"]
```

- 同时配置 `allow_users` 与 `allow_chats` 时取交集；
- `access = "admins"` 档案、高风险确认审批（`approve`）、`target_chat` 跨群调度及受限线程检索均按真实 `source_msg_id` 反查 `trusted_sources` 验权（排除插件代投消息；宿主攒批后的 `context.user_id` 不授予权限）。

## 六、凭据使用习惯与 MCP 外部连接中心（`abilities/services.json`）

### 1. 直发临时密码 & 可选密码保险箱（`/vault`）

- **用户直接发密码做事绝不拒单**：管理员或用户直接在聊天中提供临时密码、API Token 或私钥块请求跑任务时，直接通过临时环境变量传给任务线程（输出自动脱敏、不写进永久保险箱、不进聊天明文日志）。
- **密码保险箱（可选项）**：适合想给长期密码起个别名、避免以后重复发送的场景；管理台「设置 → 密码保险箱」仅采用**别名 + 密码**保存，查看条目只显示别名与保存日期、不回显密码内容；核验管理员私聊也可用 `/vault set <别名> <密码>` 录入。

### 2. 外部连接：`abilities/services.json`（MCP 连接中心 & `@API`）

`services.json` 收敛为 4 个节点（已移除静态命令 `templates`）：

- **`servers`（stdio & 远程 Streamable HTTP MCP）**：
  - 在「能力 → 外部连接」支持**粘贴标准 `mcpServers` JSON 自动填入**、切换「本机程序（自动解析 `npx`/`uvx`/`python3` 等裸命令路径）」或「远程网址（HTTP/HTTPS JSON-RPC）」、**直接在 MCP 配置里填密码/环境变量或请求头（后台用内部句柄加密，不污染用户密码保险箱列表）**；
  - 点击 **`测试连接并获取工具`** 可即时建连发现全部工具并自由勾选（未筛选默认通配 `["*"]`）；
  - 当支持 `toolsets` 的角色绑定某个 MCP 或 `@API` 后，运行时自动开放 `mcp_call` / `plugin_api` 工具，无需手工改工具列表。
- **`apis`（跨插件 `@API`）**：底层调用宿主 `api.list` / `api.get` / `api.call`；在「外部连接」右栏发现宿主接口后可一键登记给角色使用（普通群聊仅开放只读接口，写接口仅限管理员）。
- **`web`（自定义联网源）**与 **`inputs`（平台文件读取器）**：与宿主联网及平台只读读取 MCP 衔接，将媒体/文档安全落入线程 `in/` 目录。

> 注：**外部事件推送 Webhook（`incoming.py`）已永久移除，不再恢复**。持续检查、网页变动或特定事件监控一律使用收敛后的单一心跳与 **`maisya_later(mode="watch")`** 条件盯梢。

## 七、条件盯梢（Watch）替代历史 Webhook

为消除高维护成本与额外签名转发复杂度，`v0.3` **已移除** `webhooks.json`、`maisya/incoming.py` 与外部 `maisya_incoming_event` 接口，改为由原生 `maisya_later(action="schedule", mode="watch", ...)` + `Pulse` 统一承担持续监测：

- **工作方式**：安排周期性静默巡检（`every_seconds >= 300`）并填写自然语言触发条件 `condition`（例如监控某接口状态、某仓库新版本或特定群内公告）。
- **静默不刷屏**：巡检到期时在后台独立工作区注入 `<watch_contract>` 与近 3 次检查摘要 `<previous_runs>` 对比基线；若未满足条件，线程仅输出 `[WATCH:NO_CHANGE]`，只刷新 `last_checked_at`，**不唤醒群聊、不发任何消息、也不消耗每日主动额度**。
- **命中才汇报**：一旦满足 `condition`，自动产出结论与可选图卡附件并按权限路由汇报（管理员安排的巡检受 `scheduled_admin` 保护，非管理员不可取消）；在管理台「现场 → 预定与盯梢」支持查看最近检查与触发状态，以及随时暂停（`intent_pause`）、恢复（`intent_resume`）、立即巡检一次（`intent_run_now`）或取消。
