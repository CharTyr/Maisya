# 开发入门

开发前先读根目录 [AGENTS.md](../AGENTS.md)（线上红线与设计中心）与 [codemap.md](../codemap.md)。

当前整体状态：M0–M6 全部能力与设计期望对齐均已实现，支持宿主统一联网预设及第三方麦麦联网搜索插件/只读服务自动兼容；累计 194 项本地测试（含 2 项 Chromium 浏览器 UI 测试）、21 项真实宿主 SDK 隔离契约、隔离实模第三方联网冒烟与独立 Docker/runsc 运行时验收通过。使用与接入见 [管理台与接入](04-管理台与接入.md)。

## 现行设计期望对齐要点

- **联网搜索路由**：`web_provider` 默认 `"auto"`，优先调用宿主预设 `web.search` / `web.fetch`；当宿主未启用统一联网时自动兼容 `services.json["web"]` 或 `xxxxx7258.google-search-plugin`（按需只读 `config.get_plugin`，支持多引擎回退与单次作用域脱敏，纯标准库 SSRF 防护与重定向拦截），不替代也不屏蔽其他插件的 `@Tool`。

- **开箱能力与预设**：首次初始化释放 `presets/skills/source-checking/SKILL.md`、`presets/skills/ongoing-workspace/SKILL.md` 与 `presets/memory/HEARTBEAT.md`（脾性基线 + 空白探索方向）；`scout`/`maker` 自带职责边界说明，无需从零编写提示词即可使用。
- **跨插件只读 `@API`**：`_manifest.json` 声明 `api.list` / `api.get` / `api.call`；管理员可在 `abilities/services.json` 的 `"apis"` 节点登记白名单并在 `profile.toml` 通过 `tools = [..., "plugin_api"]` 与 `apis = [...]` 授权只读调用（适配 SDK 自动解包 `result` 字段，含 `None`/`0`/`[]`）。
- **`planner` 与交付细节**：`before_planner` 在 `<maisya_profiles>` 暴露 `summary` / `autonomous`、省略空上下文段、保留 `maisya_later` 提示，并在管理员发言时提示 `maisya_shape`；`Share` 将 `file` 附件从图文主消息中拆出，于主消息之后单独调用 `send.hybrid` 跟发（带 `sync_to_maisaka_history=True`）。
- **克制主动性与事件先跑线程**：支持按会话覆盖主动级别 `chat_proactive_levels`、冷私聊熟人名册 `acquaintance_users`、久违想念静默阈值 `longing_quiet_hours`（配合 `session_routes.human_count` / `last_human_at`）、`owner="self"` 探索通过 `thread_later(kind="serendipity")` 向投缘活跃会话提议偶遇、以及 `webhooks.json` 绑定自主 `profile` + `workspace` 先跑线程再由 Pulse 转达。
- **玻璃盒现场与设置**：现场页 `console.py` 提供 `system` / `memory` / `user` / `assistant` / `tool` 五段上下文统计与 `scheduled_intents` 摘要，支持勾选「立即转向（`steer`）」递纸条；设置页支持编辑 `chat_proactive_levels`、`acquaintance_users` 与 `longing_quiet_hours`。

## M3 当前入口（2026-11-12）

执行代码与验证记录见 [M3 执行方案](03-M3执行方案.md)。当前累计 139 项非浏览器测试、1 项 Chromium 页面测试与真实宿主 17 项 SDK 契约通过；真实 gVisor 与网络/资源边界验收等待线上授权。源码默认 `sandbox.enabled=false`。

- 开发依赖在清单中声明 `cryptography>=46,<51` 与 `jsonschema>=4.23,<5`。本地按独立环境安装，不向宿主 venv 全局补包。
- `maker` 首次加载释放到外部 `abilities/profiles/maker/`，`environment="sandbox"`、`network="public"`。启用执行需要 Linux root、本机 Unix Docker socket、专用 runsc runtime、cgroup v2、nft/ip/mount/umount/findmnt，以及固定 digest 的可信镜像；配置示例见根目录 `config.example.toml`。
- `maisya_agent(action="start",profile="maker",workspace="活动名",message="…")` 可开启或续接同名工作区；`send` 默认排队补充，`steer=true` 显式转向立即中断当前活动并替代队列中未执行的旧方向；`stop` 等待资源清理。检查点保留 project/in/out 的普通文件，cache 和依赖目录按活动重建。普通能力可由 MaiBot 自主调度。
- `ref_msg_ids` 导入当前会话的实际字节或公开下载地址；`from_threads` 可引用同会话旧结果附件。显式 `result_attach` 创建不可变句柄，planner 再选择 `share`；纯文字直接返回。平台只有 `file_ref` 时，需补可读输入。
- MCP 登记文件为外部 `abilities/services.json`：`servers.<id>` 配置绝对路径 `command`、`tools` 白名单、`readonly`、`access` 与 `credentials` 环境变量到保险箱句柄的映射；Profile 用 `mcp=["id"]` 和 `mcp_call` 授权。登记程序由管理员信任，运行时不下载模型指定代码到宿主执行。
- 私有模板登记在 `templates.<id>`，使用 `argv`、JSON `schema`、`secrets` 句柄与固定 IPv4/端口 `targets`；程序必须位于可信镜像的 `/opt/maisya/templates/`。Profile 要求 `access="admins"`、`network="restricted"` 与 `credential_call`，每次活动重新核验真实管理员来源。
- `Profiles.clone/export/import_package` 提供后端档案包操作；包含服务绑定的导入包默认未绑定，需管理员在本机重新登记后启用。管理页操作入口归 M6。

本地回归运行 `python -m pytest tests -q`，SDK 契约运行 `python3 tests_host/run_contract.py`。真实运行时脚本 `python3 tests_sandbox/run_isolated.py` 默认只显示计划；添加 `--execute` 会在共享服务器创建独立运行时和临时网络规则，必须取得当次授权再运行。

## M4 记忆与塑形（2026-11-12）

当前累计 151 项非浏览器测试、1 项 Chromium 页面测试、18 项真实宿主 SDK 隔离契约通过。

- `maisya_shape` 是管理员延迟工具，`source_msg_id` 必须来自当前会话最近 300 秒内的真实管理员消息；`user_id` 不能授予权限。`kind` 支持 `profile / notes / skill / memory / journal / heartbeat`。
- `read` 返回内容与 `version`；`write` 使用整篇新内容和 `expected_version`；`history` 返回最近 30 个版本的元数据；`rollback` 使用目标 `version` 和当前 `expected_version`，回滚会新增版本。并发版本冲突须先重新读取。`create(kind="profile",target="新编号",base="scout")` 从底座克隆；新技能和记忆用版本 0 写入。
- `profile` 目标文档为 `PROFILE.md` 或 `profile.toml`；`notes` 为该档案的 `NOTES.md`；`skill` 为全局 `abilities/skills/<id>/SKILL.md`。`profile.toml` 用 `skills=["id"]` 绑定技能。方法与模型说明每次请求重新加载，执行权限仍经真实来源与档案边界检查。
- 会话记忆最多 2,200 字，仅从可信工具上下文确定原会话。目录使用会话 ID 的 SHA-256 前 32 位，避免路径越界；planner、该会话 Agent 与原生 Replyer 获得该会话记忆。`JOURNAL.md` 仅收公开自身线程的结果，按 UTC 日期保留 7 天、最多 1,500 字；完整经历仍在线程中可检索。
- `maisya_recall` 增加 `kind="threads|experiences|memory|journal|all"`，默认 `all`。`experiences` 仅查自身线程；`scope="chat"` 时不返回自身近况，`scope="self"` 不返回会话记忆。FTS5 与中文子串查询均按会话过滤。
- 文件是当前正文，SQLite 记录版本、来源与检索索引。API 修改采用独占锁、版本校验和原子文件替换；有效的外部文件编辑在下一次读取时记为 `external` 版本。档案配置验证失败时恢复原文。
- 自动笔记只在同一工具失败后恢复时运行，摘要请求只含内置工具名和成败状态，最多 500 token；不传会话正文、原始参数、输出、用户或工作区标识。每次活动最多提炼一次，最多 8 个待处理活动、串行调用、10 秒超时，笔记满 1,800 字后停止提炼。密钥、邮箱、数字标识、地址和已知会话片段匹配检查失败时拒绝写入；管理员明确指正直接走塑形，正常活动不额外调用模型。

M4 的对话权限、版本回滚、上下文与摘要调用边界已通过测试替身和真实 SDK 验证；M3 的真实运行时验收仍按执行方案单独授权。

## 真实宿主契约测试（服务器隔离目录，绝不碰线上 `plugins/`）

每次修改 `_manifest.json`、`webui.json`、插件生命周期或组件注册后，必须在唯一隔离目录跑 `tests_host/`：

## M1 使用与验证（2026-11-12）

M1 已实现只读探索线程、消息续接、停止和检索。`maisya_agent` 与 `maisya_recall` 是两个可见工具；启用会话有可用的 `scout` 时，仅剔除宿主三个同名内置 `subagent` 工具。未启用会话隐藏 Maisya 工具；受限档案同时经过本轮消息可见性和执行时真实发言人检查。

- 开启：`action="start"`、`profile="scout"` 与 `message`。MaiBot 自主调用普通只读能力可省略 `source_msg_id`；根据用户消息发起时提供真实来源，受限能力必须核验来源与权限。默认等 `20` 秒，可用 `wait_seconds=0` 并行开启多个线程。
- 补充或继续：`action="send"`、`thread_id` 与 `message`，沿用同一来源规则。新消息进入原线程后，在模型返回和每个工具执行前检查转向；旧方向尚未执行的调用跳过，已完成的工具结果保留。
- 停止：`action="stop"`。MaiBot 可自主停止普通只读线程；带用户来源时核验原发起人或管理员，受限线程始终要求真实授权。停止后拒绝迟到的模型结果与新工具调用；宿主上游模型 RPC 能否同步提前结束仍需联调确认。
- 查阅：`maisya_recall(query, scope, limit)`。支持会话隔离、自身经历检索、中文子串和线程编号精确查询。

`scout` 首次加载时释放到外部数据目录 `abilities/profiles/scout/`，以后不覆盖用户编辑。空 `model` 使用宿主 `utils` 模型路由；具体模型与备用模型在 `profile.toml` 设置。联网复用宿主 `web.search` / `web.fetch`，需要宿主已配置统一联网服务。识图单独走宿主视觉模型，原始图片字节不进入主探索上下文与线程记录。在线文档通过网页读取；群文件实体解析在 M3 的沙箱中实现。

默认每轮最多 `16` 次模型请求、最长 `180` 秒，最多 `8` 个活动线程。单线程最多积压 `32` 条补充。上下文预算 `thread_context_chars` 默认 `48,000` 字符；预算内完整保留，超过后将原始消息和工具结果完整归档到本线程事件，保留可用上下文与回读索引。线程内 `thread_read` 可按关键词定位事实、理由和出处，再按事件编号分页读原文；它不增加 planner 可见工具。闲置 `900` 秒后的续接检查同样遵循这一预算，不因时间经过而截断前情。检索索引保留各轮输入与结果，旧结论不会被新结果覆盖。宿主重载后中断线程转为可继续状态，不自动重放外部调用。

验证结果：本地 SDK 2.8.1 下 **71 项单测通过**；真实宿主 1.3.20 / SDK 2.21.0 下 **12 项隔离契约通过**，包括可选来源的原生工具 schema、管理员权限、Context Item 追加、转向后成对工具消息解析、归档后原始出处回读，以及工具调度→搜索→结果→检索链路。模型和联网响应由测试 RPC 替身提供，实际服务质量与群聊联调尚未进行。源码、线上插件与宿主配置检查一致，临时目录已清理。

## M2 纯文字回接核心（2026-11-12）

已实现 `Bridge` 与处理 `return` 意图的最小 `Pulse`：

- 短窗内返回的结果直接交给当前 planner，并在原生 `maisaka.replyer` 请求中单次补入事实，保留其他插件已有的 `extra_prompt`。同一次 Replyer 生成的重试通过不透明凭据沿用事实；重试前重新检查线程是否已停止或转向。另一次回复和 `plugin.replyer` 不继承这份材料。
- 用户消息触发的线程在后台完成、需要核心输入或运行失败时，与结果事件同一事务写入 `return` 意图。意图只引用原始结果事件，不另存一份经历。
- 同一 planner 响应中、同一真实来源的线程组成回接组。宿主顺序执行各工具期间先等待组员登记；最后一次工具调用返回后留 `1` 秒合并窗口，组员全部结束或再过 `10` 秒汇合期限后，最多发起一次原会话唤醒。
- Pulse 每秒检查到期回接，调用 `maisaka.proactive.trigger`；原会话 planner 决定回复或静默。插件回接核心不直接发送文字。停止、被新方向替代、已补入回复或本轮选择静默的结果不再主动唤醒；原始结果继续可搜。
- 已完成但尚未认领的回接可在重载后继续处理，候选有效期 `10` 分钟。RPC 拒绝或接收状态不明时记录状态，不重复自动投递；结果留在会话索引和检索中。新建回接组时清理超过 `24` 小时的临时关联，保留线程原文。
- MaiBot 自主探索的后台结果进入线程索引，主动触达等后续社交分寸闸接入后处理。

累计 **89 项本地测试、14 项真实宿主隔离契约通过**。新增契约覆盖原生 SDK 的结果补入、Replyer 重试参数保留、同轮回复与停止的顺序，以及同轮两线程合并后的原会话唤醒 RPC。模型和唤醒响应使用测试替身；尚未运行真实群聊交付。服务器源码、线上插件与配置检查一致，临时目录已清理。

M2 剩余 `share` 准确载荷出口与“现场”管理页。

## M2 剩余与 M5 第一阶段（2026-11-12）

M2 剩余部分已实现：`share` 准确载荷出口走 `maisaka.reply.generate` 生成 MaiBot 原生表达、`send.hybrid` 发出链接/媒体/引用，持久认领防止重复交付，纯文字与 here.now 链接继续走原生 `reply`；`console.py` 提供玻璃盒 `@API`，`webui/now.html` 现场页支持线程列表、步骤流、上下文构成条、单路游标轮询、递纸条与停止。

M5 第一阶段已实现：

- `intents.py` 通用意图存储：`return / proactive / silent` 三类，记录来源、目标、到期、理由、线程与状态；`social_state` 表保存按 `chat_id` 的未回锁与上次主动时间。
- `maisya_later`（deferred 工具）：`schedule` 安排提醒、`list` 查看本会话待处理意图、`cancel` 取消；用户发起的提醒需 `source_msg_id` 核验，MaiBot 自主回访可留空。
- Pulse 每秒统一分发到期意图：`return` 沿用原回接组唤醒；`later` 提醒以 `maisaka.proactive.trigger` 唤醒原会话并注入 `<maisya_reminder>`；`proactive` 先过社交分寸闸再唤醒；`silent` 检查绑定线程后完结或推迟。
- 社交分寸闸：`sleep_window`（如 `23-7`，配置项）内跳过主动意图并推迟 15 分钟；Pulse 主动唤醒后对 `chat_id` 上锁，收到该会话真人消息（非插件代投）解锁；普通闲聊惦记（`proactive` 且非 `later` 来源）全局每天最多 1 条；每轮最多认领一个主动意图。

验证结果：本地 **108 项测试通过**（含 4 项意图与社交闸新测试）；真实宿主 1.3.20 / SDK 2.21.0 **16 项隔离契约通过**，覆盖 `maisya_later` 组件注册与 deferred 可见性。提醒唤醒内容使用测试替身；`proactive` 意图的来源生成（余韵、偶遇、想念）与熟人边界检查待后续里程碑。

## M5 意图与 Pulse 收尾（2026-11-12）

- `maisya_later` 增加 `kind`（`later`/`proactive`）与 `source`（`later`/`afterglow`/`serendipity`/`longing`）参数：MaiBot 可把"事后惦记、偶遇想分享、久违想念"安排为 proactive 意图，由 Pulse 统一过闸；`later` 到点直接注入 `<maisya_reminder>`。
- 主动度 `proactive_level`：`quiet` 拦截全部 proactive；`care`（默认）放行余韵/想念/定时惦记、拦截偶遇；`lively` 全放行。熟人边界：proactive 目标的会话需在 `trusted_sources` 有非代投真人消息记录，否则记 `unfamiliar_chat`。
- 线程内 `thread_later`：线程可为自己安排 60 秒至 7 天后的 `silent` 唤醒（`next_step` 作为下一步消息），Pulse 到期经 `engine.send` 推进原线程；线程运行中或已关闭时推迟或完结。
- Pulse `_silent` 真实推进：silent 意图到期时给绑定线程投递下一步消息，让多站旅行、定期检查这类持续活动按自身节奏走下去，中间进展只落线程现场不打扰会话。

验证结果：本地 **112 项测试通过**；真实宿主契约 **16 项通过**（`maisya_later` deferred、`thread_later` schema、组件集合一致）。`sleep_window` 与 `proactive_level` 已入 `config.example.toml`。意图唤醒内容与模型决策仍走测试替身；真实群聊的主动搭话效果待联调。
