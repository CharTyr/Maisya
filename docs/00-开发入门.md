## 2. 六条不能偏离的架构核心（Do-Not-Drift）

后续新增需求或修 Bug 前，先对照下面六条核对，避免回退或绕弯路：

1. **话筒属于 MaiBot Planner，插件绝不抢话**
   - `chat.receive.after_process` 永远返回 `continue`；
   - 线程结果不直接发群，而是通过 `Bridge` + `Pulse` 唤醒目标会话 `planner`，纯文字走原生 `reply` + `before_replyer` 单次事实垫入，需要精确外链/图片/文件/旧锚点时由 `planner` 调用 `maisya_agent(action="share")`。
2. **Planner 永远只见极简稳定工具集**
   - 常驻可见工具只有 `maisya_agent`、`maisya_recall`、`maisya_later` 三个；
   - 管理员配置神器 `maisya_shape` **必须保持为延迟工具（严禁加 `visibility="visible"`）**，以免触发宿主 `MaisakaReasoningEngine` 对未注册可见度的策略变化或无谓膨胀每轮词表；管理员轮次通过上下文提示先调宿主 `tool_search(query="maisya_shape")` 展开即可。
3. **非服务群零干扰，未启用仅放行已核验管理员内存引导**
   - 普通用户在非白名单会话发消息：零数据库写入、零工具暴露、零上下文注入、零外发；
   - 已核验管理员即便在未加入白名单的私聊说话，也只写进 **300 秒过期的有界内存缓存**（不落盘 SQLite），就能用 `/vault set`、`maisya_shape`、`maisya_later`、`maisya_agent` 完成跨群开通、试跑预览与每日排班。
4. **消息流双制式统一：`平台:类型:id` <-> 32 位 MD5 `session_id`**
   - 宿主内部 `chat_sessions` 的 `session_id` 是 32 位十六进制 MD5，人类配置与界面统一展示/保存为 `<platform>:<group|private>:<id>`（如 `qq:group:12345678`、`telegram:private:804200`）；
   - `enabled_for()`、`session_routes`、`trust.py`、`shaping.resolve_chat_target()` 保持双向别名映射与冷流匹配，确保群刚加白名单后第一条消息就能命中使用。
5. **模型顺序回退与绝不泄漏凭据**
   - 角色模型配置采用 `model_name`（#1 主选）+ `fallback_models`（#2..#N 备选），由 `Scout.step()` 遇到运行/超时/格式异常时顺次接棒；
   - 宿主可用模型清单经 `_sanitize_host_model_catalog` 脱敏，只存模型名、标识与供应商；所有 `api_key` / `base_url` 与 `Vault` 私密凭据绝不进入提示词、日志、SQLite 明文或文档示例。
6. **WebUI 永远先改源模板再编译，坚守零端口与 CSP**
   - 所有界面改动只在 `webui/now.html.in`、`webui/management.html.in`、`webui/fragments/*.html`、`webui/millennium.css` 和 `webui/fish.js` 进行，改完执行 `python3 webui/build.py` 生成最终 `webui/*.html`；
   - 绝不使用 `<img>`、`<iframe>`、`transition: all`、`localStorage`/`sessionStorage` 或外部 CDN；顶栏双主题默认「千禧机械（`millennium`）」，同步支持「清朗手账（`maiwork`）」与「自动（`auto`）」。

## 3. 本地开发与全套验证命令

在仓库根目录（`Maisya/`）下运行：

```bash
# 1. 修改 WebUI 模板/样式后编译并检查一致性
python3 webui/build.py && python3 webui/build.py --check

# 2. 运行本地全部单元与 Playwright Chromium UI 测试（当前 236 项）
PYTHONPATH=.:.local-checks/deps ~/.venvs/maiwork/bin/python -m pytest tests -q -rs -p no:cacheprovider

# 3. 验证真实 MaiCore / SDK 宿主契约（要求独立 MAIBOT_INSTANCE_DIR，不改宿主）
python3 tests_host/run_contract.py

# 4. 格式与干净度检查
git diff --check
```

补充专项验证（按需执行）：
- **沙箱隔离验收**（确认宿主环境支持 Docker + `runsc`）：
  `python3 tests_sandbox/check_runtime.py` 与 `python3 tests_sandbox/run_isolated.py --execute`
- **无额外端到端冒烟**（隔离实例实调工具链）：
  `python3 tests_host/run_live_smoke.py --execute`

## 4. 安全部署与 Git 协同规范

1. **禁止触碰宿主与禁重启**：所有部署严格只覆盖远端 `plugins/CharTyr_Maisya/`，绝不修改 MaiBot 核心代码、`config/bot_config.toml` 或同级插件，也绝不由脚本重启宿主服务。
2. **先备再同（原子热重载）**：
   - 将远端旧 `CharTyr_Maisya`、运行时数据目录及活跃 SQLite（**必须通过 `sqlite3 ...?mode=ro` `.backup()`**，严禁直接 `cp` 活库）归档至 `/root/backups/`；
   - 先在临时 staging 目录解压运行时清单并核验 `python3 webui/build.py --check`，再原子替换进 `plugins/CharTyr_Maisya/`，保留线上真实 `config.toml` 与 `config_back/`，不带入 `tests/`、`.trellis/`、`.git/` 或本地密钥。
3. **开源仓库隐私底线**：
   - 公开提交历史、测试用例与截图仅使用虚拟演示身份（如 `qq:group:100246809` / `独立开发社` / `telegram:private:804200`）；
   - 禁止执行 `git add .`，通过显式路径 `git add <file>...` 提交；`.trellis/` 等个人工作流辅助目录已在 `.git/info/exclude` 局部屏蔽。
